# 外電譯文:人工交付流程

**刻意不接 API 金鑰**(使用者的決定:不把憑證交出去)。改走本站既有的
「收件匣 → 核對 → 發布」慣例,跟外電摘要、租借、教練職涯同一套。

## 三步

```bash
# 1. 產生待翻清單(含可直接複製的提示詞)
cd epl && npm run news:todo -- --out=待翻清單.md

# 2. 把 待翻清單.md 的內容貼給任何 AI 助手或自己翻,
#    回來的 JSON 存成 data/manual/news-zh.json

# 3. 核對並發布
npm run news:zh
npm run build          # 三個聯賽都翻的話:laliga:build / en2:build / build
```

## 交付檔長什麼樣

```json
{
  "by": "human",
  "entries": {
    "6f1ecadc1e0cb08b": { "ok": true, "title": "中文標題", "body": "中文摘要" }
  }
}
```

- `by` **照實填**:自己翻的寫 `human`,用模型翻的寫模型名。
  前端會據此標「人工翻譯」或「機器翻譯」——
  **把機器翻譯講成人工翻譯是說謊**(鐵則四),反過來只是保守。
- `key` 是「標題+摘要」的雜湊,由 `news:todo` 產生,**不要改**。
  用它當鍵是因為 RSS 的 id 是「來源+序號」,序號會隨新文章位移。
- 翻不了的那一則 `ok` 填 `false`、`title` 留空 —— **不要猜**。

## 核對器擋什麼

翻譯的正確性沒辦法自動驗(那要另一個翻譯來對,等於換一個地方猜)。
所以只擋「結構上一定錯」的四種,而且**逐筆印出來**:

| 擋掉的情況 | 為什麼 |
|---|---|
| key 對不到現存外電 | 清單過期了(外電會滾動,舊的會被擠掉) |
| `ok: false` 或標題是空的 | 譯者自己說翻不了 |
| 譯文跟原文一模一樣 | 那是沒翻,不是翻譯 |
| 標題裡沒有任何中文字 | 同上,擋整批複製原文 |

## 不用怕重複翻

譯文依內容雜湊**永久快取**,`news:todo` 只列還沒翻的。
第一次要翻約 120 則,之後每天只有新增的那十幾則。
