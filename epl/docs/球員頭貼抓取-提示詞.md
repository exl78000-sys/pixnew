# 提示詞:抓取英超球員頭貼

> 把 `---` 之間的內容整段複製給你的 AI 助手。
> 它需要:能連外網、能跑 Node 或 Python、能處理圖片(sharp / Pillow / ImageMagick 擇一)。
>
> **必須一併提供的輸入檔**:`epl/data/manual/photo-manifest.json`(599 名球員的清單,已產生)

---

## 任務

抓取 599 名英超球員的頭貼,處理成指定格式,產出**一個 JSON 檔**。

我會給你一個清單檔 `photo-manifest.json`,長這樣:

```json
{
  "_count": 599,
  "players": [
    { "code": "223340", "photo": "223340.jpg", "optaCode": "p223340",
      "name": "Saka", "fullName": "Bukayo Saka", "team": "ARS", "pos": "MID" }
  ]
}
```

`code` 是關鍵 —— 它同時是頭貼 ID 和我這邊資料庫的鍵。**輸出必須用 code 當鍵**,不要用名字(有重名、有特殊字元)。

## 第一步:先確認哪個網址格式有效(不要跳過)

英超的圖片 CDN 換過命名規則,我無法從我的環境測試(被防火牆擋住)。
**請你先用 Saka(code = 223340)測這幾個候選,找出哪個回 HTTP 200**:

```
https://resources.premierleague.com/premierleague/photos/players/250x250/p223340.png
https://resources.premierleague.com/premierleague/photos/players/110x140/p223340.png
https://resources.premierleague.com/premierleague25/photos/players/250x250/223340.png
https://resources.premierleague.com/premierleague26/photos/players/250x250/223340.png
https://resources.premierleague.com/photos/2024/players/250x250/p223340.png
```

規律是 `{size}/p{code}.png` 或 `{size}/{code}.png`,尺寸常見 `110x140`、`250x250`。
如果全都失敗,到 https://www.premierleague.com/players 隨便開一名球員的頁面,
從 HTML 或 network 面板抄出實際的圖片網址,推導出當前規則。

**先把你找到的有效網址格式告訴我,再開始批次下載。**

## 第二步:批次下載與處理

- **禮貌抓取**:每次請求間隔至少 200ms,失敗重試最多 3 次(指數退避)。
  這是別人的 CDN,不要開 50 條連線硬幹。
- **處理**:等比例縮到 **寬 96px**(高度自動),轉成 **JPEG 品質 78**,背景填 `#1a1420`
  (原圖多半是去背 PNG,直接轉 JPEG 會變黑底或白底,跟深色網站不搭)。
- **每張目標 3 KB 以內**。若平均超過,把品質降到 70 再試一次。

### 為什麼是 JPEG 不是 PNG

頭貼是照片。PNG 對照片的壓縮效率極差 —— 599 張 PNG 會是 6~20 MB,
JPEG 只要 1.5~2 MB。這個專案的成品要塞進單一 HTML 檔(上限 16 MB),
差這一個數量級就是能做與不能做的差別。

## 第三步:輸出格式(請嚴格照這個結構)

檔名 `photos.json`,內容:

```json
{
  "_note": "球員頭貼(自動產生,請勿手改)。",
  "_source": "<你實際使用的網址格式,例如 https://resources.premierleague.com/premierleague/photos/players/250x250/p{code}.png>",
  "_license": "頭貼版權屬英超聯盟與各攝影授權方,此處僅作為分析工具的識別用途。",
  "_width": 96,
  "_format": "jpeg",
  "_quality": 78,
  "_updated": "YYYY-MM-DD",
  "_count": 587,
  "_missing": ["123456", "789012"],
  "photos": {
    "223340": "data:image/jpeg;base64,/9j/4AAQSkZJRg...",
    "154561": "data:image/jpeg;base64,/9j/4AAQSkZJRg..."
  }
}
```

規則:

1. `photos` 的**鍵是 code 字串**,值是完整的 data URI(含 `data:image/jpeg;base64,` 前綴)。
2. 抓不到的球員**不要放進 photos**,而是把 code 收進 `_missing` 陣列。
   缺圖是正常的(新援、剛升上一隊的年輕球員常常沒照片),**不要用佔位圖填充**,
   我這邊會自己退回顯示隊徽。
3. `_count` 是 `photos` 實際的筆數,不是 599。
4. JSON 不要縮排(檔案會小很多),但 `_` 開頭的中繼欄位要保留。

## 第四步:交付前自我檢查

請實際跑過這幾項再交:

- [ ] `photos` 的鍵全部出現在 manifest 的 code 裡(沒有多出來的)
- [ ] `_missing` 加上 `_count` 等於 599
- [ ] 隨機抽 5 張解碼出來看,確認是**正確的球員本人**、不是佔位圖或錯誤頁面
      (CDN 有時候 404 會回一張 1x1 或預設剪影,那種要當成抓不到)
- [ ] 檔案總大小 **2.5 MB 以內**。超過就降品質重跑。
- [ ] JSON 能被 `JSON.parse` 讀進來不報錯

把最終檔案、以及「有效網址格式 / 成功幾張 / 檔案多大」回報給我。

## 不要做的事

- 不要改 manifest,也不要自己去別的網站找球員清單 —— 以我給的 599 筆為準。
- 不要抓 500x500 之類的大圖再說「之後可以縮」,直接照規格輸出。
- 不要把圖片存成 599 個獨立檔案,我要的是單一 JSON。
- 不要為了湊滿 599 張而用別的來源(維基百科、Getty)混進來 —— 
  來源不一致會讓授權說明失去意義。抓不到就記在 `_missing`。

## 拿到檔案之後(這部分我來做,你不用管)

1. 放到 `epl/data/manual/photos.json`
2. build 會把 data URI 併進 `players.json`
3. 前端 `playerPhoto(code)` 有圖用圖,沒圖退回隊徽

## 為什麼要這麼麻煩

這個網站的成品之一是**單一 HTML 檔**,可以離線雙擊開啟,發布出去的 Artifact
也有嚴格的 CSP —— 外部圖片一律被擋。所以圖片必須內嵌成 data URI,
而內嵌就對檔案大小極度敏感。這不是潔癖,是這個發布形式的硬性限制。
