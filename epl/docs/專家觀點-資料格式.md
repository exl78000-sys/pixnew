# 賽後名宿／專家觀點

真人觀點與本站 AI／統計模板永遠分開。前端只讀建置後的 `web/data/experts.json`,
使用者開頁不會搜尋新聞、不會呼叫 LLM,也不會接觸 API key。

## 新增一筆資料

在 `data/manual/expert-opinions.json` 的 `matches` 加入比賽鍵。比賽鍵格式為
`賽季|主隊代碼|客隊代碼`,例如 `2026-27|ARS|COV`。

```json
{
  "version": 1,
  "updatedAt": "2026-08-25",
  "matches": {
    "2026-27|ARS|COV": [
      {
        "id": "來源與日期組成的唯一代碼",
        "category": "news",
        "expert": "專家姓名",
        "role": "名宿／評論員",
        "publisher": "媒體名稱",
        "publishedAt": "2026-08-22T12:00:00Z",
        "url": "https://原始來源",
        "sourceType": "broadcast",
        "summary": "至少二十字、由人工核對原始來源後改寫的中文摘要。",
        "topics": ["壓迫", "換人"],
        "evidence": ["可對應本站實際 xG 或陣型的說明"],
        "reviewedAt": "2026-08-25T10:00:00Z",
        "verified": false
      }
    ]
  }
}
```

`sourceType` 只接受 `article`、`broadcast`、`video`、`podcast`、
`press-conference`。先以 `verified:false` 保存草稿,人工確認姓名、身分、來源與摘要後
才改成 `true`;未核對草稿不會出現在前端。

`category` 只接受三種值：`news`（具名記者／新聞分析）、`legend`（退役名宿／評論員）、
`expert`（教練、資料分析師、戰術作者或當事球員）。同一篇賽後頁可以同時收錄不同人物，
但同一場、同一人物、同一原始頁不能重複。前端會依分類切換，並一次只顯示一張觀點卡。

第一版不接受 `quote` 欄位,只接受摘要。這樣可以避免把錯誤逐字稿掛到真人名下,
也避免大量重製受版權保護的原文。每一筆都必須保留 HTTPS 原始連結。

完成後執行 `npm run build`。建置器會擋住缺欄位、錯比賽、重複來源、無效網址、
未支援來源類型與直接引言。
