# 英冠教練名冊 —— 交付提示詞

把下面整段交給協作方。跟球隊資料那份(`英冠-球隊資料-交付提示詞.md`)同一套方法:
對照組、逐欄位出處、null 優於猜測。那一份的成績是對照題 12/12 全對、36 隊全數採用。

---

## 給協作方的內容(以下整段複製)

### 你要做的事

補齊 **30 支球隊的現任總教練**:英冠(EFL Championship)2026-27 賽季的 24 支,
加上 6 支英超球隊。

**那 6 支英超球隊是對照組,先講明**:本站每天跟英超官方核對現任教練,
你交回來的這 6 筆我們手上有正確答案。上一次的球隊資料交付,12 支對照組
逐欄位全對,那是整份被採用的主要依據 —— 這次同樣。

| 欄位 | 說明 | 沒有把握時 |
|---|---|---|
| `name` | 現任總教練全名(官方拼法) | 回 `null` |
| `nat` | 國籍(繁體中文,例「西班牙」) | 回 `null` |
| `since` | 上任日期,`YYYY-MM-DD`;只知道月份就 `YYYY-MM` | 回 `null` |
| `caretaker` | 是否看守教練(true / false) | 回 `null` |

**日期特別重要**:本站會拿 `since` 去切分比賽、自動算任內戰績 ——
日期錯一個月,戰績就會算到前任頭上。寧可 `YYYY-MM` 也不要精確但錯的日子。

### 交付格式

```json
{
  "source": "你用了哪些來源(具體到網站名)",
  "retrievedAt": "2026-08-29",
  "coaches": [
    {
      "code": "MID",
      "en": "Middlesbrough",
      "name": "…",
      "nat": "…",
      "since": "2025-06-14",
      "caretaker": false,
      "sources": {
        "name": "https://…",
        "since": "https://…"
      }
    }
  ]
}
```

`code` 與 `en` 照抄下面的清單,不要改。`sources` 是**逐欄位**出處網址,
核對對不上的欄位會回去看你引的那一頁,引不出來的欄位不採用。

### 規則(決定採不採用)

1. **不確定就回 null。** 交回來 20 筆正確 + 10 筆 null,
   比 30 筆裡混 3 筆錯的好得多 —— 錯的教練名字掛在球隊頁上,讀者不會知道那是錯的。
2. **教練異動很頻繁,查「現在」的。** 尤其剛升降級的球隊(WOL、WHU、BUR 從英超
   降下來;BOL、CAR、LIN 從英甲升上來)——換季常伴隨換帥,別拿上季的名單照抄。
3. **看守教練要標。** `caretaker: true` 而且 `since` 填看守開始的日期。
   看不出是不是看守就 `caretaker: null`,不要猜 false。
4. **不要整批複製再改。** 之前的租借交付出現過整批複製只改年份,我們驗得出來,
   驗出來整批不採用。
5. **同一個區塊有一筆被證明是錯的,整批不採用。**

### 我會怎麼核對

- **對照組 6 筆**跟英超官方的每日名單比對,錯一筆整份重審。
- **英冠 24 筆**拿本站的英冠外電庫(BBC、Guardian,每日累積)比對 ——
  教練名字會出現在戰報裡;交付的名字如果在近期外電完全沒出現過,會標記人工查。
- **日期合理性**:不在未來、不早於球隊成立、不晚於你交付的日期。
- 之後每次比賽的戰報都會再驗一次(報導裡的教練名 vs 名冊)。

## 給下一個接手的人(不要交給協作方)

- 收件匣:`epl/data/manual/championship-coaches-delivery.json`。
  **要先寫核對器**(比照 `verify-championship-teams.mjs`:對照組、sha、
  整批退回),build 只讀核對後的產物。對照組的答案在
  `web/data/official.json` 的 `managers`(pulselive 每日核對)。
- 名字比對用 `lib/names.mjs`,不要自己再寫一份正規化。
- `since` 收下之後可以拿英冠賽果自動算任內戰績(比照英超教練的做法),
  那是把日期「用起來」的第一個地方 —— 也是日期錯誤會現形的地方。
