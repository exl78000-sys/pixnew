# 交付格式 —— 德甲 / 義甲 / 法甲的球隊資料與教練

這一份是給**交付方**看的規格。本站的規矩是 **收件匣 → 核對 → 產物**,
build 只讀產物 —— 交付檔直接寫進名冊等於把核對整個繞過去。
協作方自報「都檢查過了」不算數(鐵則五:實際踩過,自報 0 筆不符的交付,
拿獨立來源逐場核對出 39 場)。

核對器已經寫好而且測過,**交付一到就能跑**:

```bash
npm run de1:verify-teams     # 也可 it1 / fr1;不帶 --league 就三個都跑
npm run de1:verify-coaches
```

沒有收件匣時它會印「還沒有收件匣,略過」——那不是錯,是在等你。

## 一、球隊資料

**收件匣路徑**(三選一,看你交哪個聯賽):

| 聯賽 | 收件匣 |
|---|---|
| 德甲 | `data/manual/bundesliga-teams-delivery.json` |
| 義甲 | `data/manual/serie-a-teams-delivery.json` |
| 法甲 | `data/manual/ligue-1-teams-delivery.json` |

```json
{
  "source": "你從哪裡整理的(一句話)",
  "retrievedAt": "2026-09-16T00:00:00Z",
  "teams": [
    {
      "code": "FCB",
      "en": "Bayern Munich",
      "colors": ["#RRGGBB", "#RRGGBB"],
      "city": "慕尼黑",
      "venue": "安聯球場 Allianz Arena",
      "capacity": 75000,
      "nickname": "拜仁",
      "sources": {
        "colors":   "https://…",
        "city":     "https://…",
        "venue":    "https://…",
        "capacity": "https://…",
        "nickname": "https://…"
      }
    }
  ]
}
```

### 規矩(這幾條是核對器會擋的)

1. **`code` 要用本站名冊裡的隊碼**(`data/manual/teams-{聯賽}.json`),不要自己編。
2. **每一格有值就要有 `sources[欄位]`**,而且要是能點開的網址。
   **沒有出處的那一格不採用** —— 核對時對不上要回得去看。
3. **不確定就給 `null` 或整個不給,不要猜。**
   缺一格畫面上會標「未取得」;填錯的讀者不會知道。這是鐵則三。
4. `colors` 第一個是主色(球衣主色,不是隊徽主色 —— 兩者可以不同)。
5. `capacity` 是整數,合理區間 5,000 ~ 85,000。
6. 同一座球場給兩隊用時,`capacity` 必須一致。

### 核對器會做什麼

| 檢查 | 德義法 |
|---|---|
| 對照題(跟本站既有答案逐欄位比) | **做不了** —— 本站沒有這三個聯賽的既有答案 |
| 隊色 vs 隊徽(抽隊徽主色比 ΔE) | 可以,隊徽 100% 齊全 |
| 容量量級 + 同場館一致 | 可以 |
| 逐欄位出處 | 可以 |

**對照題做不了這件事很重要**:英冠的交付清單裡刻意留了 12 支本站早就有答案的球隊,
對不上就整份退回 —— 那是最硬的一關。德義法沒有這一關,所以**逐欄位出處變成主要的把關**,
請務必每一格都附網址。

還有一件事要先講明白:**隊色那一關是「抓離譜」不是「驗證正確」**。
門檻 ΔE 40 是刻意寬的(球衣跟隊徽本來就可能不同)。實測過它的鑑別力:
拿亮綠 `#00FF00` 當多特蒙德的主色,ΔE 只有 20,照樣會通過。
所以核對器會把**差最多的三隊**印出來讓人看一眼 —— **通過不等於對**。

## 二、教練

| 聯賽 | 收件匣 |
|---|---|
| 德甲 | `data/manual/bundesliga-coaches-delivery.json` |
| 義甲 | `data/manual/serie-a-coaches-delivery.json` |
| 法甲 | `data/manual/ligue-1-coaches-delivery.json` |

```json
{
  "source": "你從哪裡整理的",
  "season": "2026-27",
  "coaches": [
    { "code": "FCB", "name": "Vincent Kompany", "since": "2024-05-29", "source": "https://…" }
  ]
}
```

- `name` 用**原文拼寫**(Sebastian Hoeneß 的 ß 不要換成 ss;本站的姓名正規化處理得了)。
- `since` 是 `YYYY-MM-DD`,不確定就不要給(不要填一個大概的)。
- `source` 必須是 https 網址,沒有的那一筆不採用。

### 核對器會做什麼 —— 這一關比英冠那套強

獨立來源是**本站逐場正式名單裡的教練欄**(FotMob,已經在倉庫裡,核對不花任何請求)。
實測德甲本季 18/18 隊都有。

| 結果 | 意思 |
|---|---|
| `confirmed` | 交付的名字 = 本站最後一場正式名單上的教練 |
| `conflict` | 對不上 → **硬傷,整份不採用**(通常代表交付過期,換帥之後沒更新) |
| `unverified` | 本站沒有這一隊的逐場名單 → 查不動,**照實記,不算 confirmed** |

「無法核對 ≠ 一致」是本站的老規矩,等級會跟著資料走到畫面上 —— 不會混成一句「有教練資料」。

## 三、交付之後

跑核對器 → 通過才會產生 `data/{聯賽}-teams-verified.json` / `-coaches-verified.json`,
build 只讀那兩份。**有一筆被證明錯就整份不採用**,不挑著用 ——
從兩個對不上的來源裡選一個喜歡的答案等於沒有核對(進球明細與 Alaves 那兩次的教訓)。
