一、現在就壞的

使用者已經看得到

實測 8 個頁面 × 2 個聯賽,只有這一項是真的破口。已經修掉了 —— 下面留著原始診斷,因為它解釋了為什麼修法要那樣寫。

已修 西甲的戰術頁與球員頁吐出開發者訊息

tactics.html?league=es1 與 players.html?league=es1 會停在轉圈畫面,底下附一行 「載入失敗:讀取 data/leagues/es1/formation.json 失敗(404)。請先執行 npm run build」。

兩個問題:那是給開發者看的訊息,不是給讀者的;而且理由是錯的 —— 真正的原因是西甲還沒有這一頁的資料,不是誰忘了 build。 導覽列在西甲模式下本來就只開放三頁,所以一般點擊不會走到這裡, 但只要有人存過網址、或從搜尋進來就會撞上。

做法 —— 由聯賽自己宣告開放哪幾頁(LEAGUES[lg].open), 導覽列與缺口判斷共用同一份宣告。以後補齊一頁只要加進 open, 守衛自動消失,不必記得改第二個地方。連請求都不發,瀏覽器 console 也不再留 404。
界線 —— 單場分析不擋。它是從賽程表點進去的,西甲有比分、預測、 市場機率與兩隊風格對比,真的做得出來;一起擋掉等於砍掉一個能用的功能。 這條有專門的斷言守著。另外五頁(實時戰況、戰術、球員、動態、模型驗證) 都改成同一張空狀態:說明這一頁靠什麼資料、列出西甲現在看得到的頁面、 附一個切到英超同一頁的連結。

已完成 西甲球員資料源

原本規劃寫的是「同一把 API-Football 金鑰就能拿到球員名單」。 那是錯的,而且是實測推翻的 —— 那把金鑰是 Free 方案, 只開放 2022–2024,league=140 的本季與上季都回 plan 錯誤。

改走 Understat,結果比原路更好: POST /main/getPlayersStats/ 帶 league=La_liga&season=2025, 一個請求回整季 600 名球員——原路要分頁抓 25–30 次。 找到它的過程本身值得記:聯賽 HTML 頁只端 18 KB 外殼、一個資料變數都沒有, getLeaguePlayers 是 404,第三個候選回的是 {"error":{"error_code":4}}——回結構化錯誤而不是 404, 代表端點在、只是少參數。在前兩個就下結論就錯過了。

界線 —— Understat 沒有背號、頭貼、傷停、防守數據。 所以西甲球員頁不是英超那一頁的複製品,頁首直接列出缺什麼。 留一排永遠空白的欄位比不做更糟。
順帶抓出一個線上的謊 —— 西甲賽後資料「0/11・完賽後抓取一次並永久快取」 讀起來像在等,其實是同一個 plan 限制,永遠等不到。三處文案都改成講實話, 而且原因由抓取端記錄、換方案後自動恢復,不必記得回來改。

三、SportMonks:實測拿得到什麼

2026-08-26 · 兩輪探測

方案 Starter(Advanced),額度 每小時 2000 次 —— 對比 API-Football Free 的每天 100 次,差 480 倍。 重跑實測:npm run probe:sportmonks(硬上限 12 個請求)。

確認可用 本季拿得到,五大聯賽都在

英超 8、德甲 82、法甲 301、 義甲 384、西甲 564。 西甲三季:27965 2026/2027(本季・進行中)、 25659 2025/2026、23621 2024/2025。

本季拿得到 —— 這正是 API-Football 死掉的那一題。同一個坑,這次過了。

欄位UnderstatSportMonks意義
進球、助攻、xG、xA、關鍵傳球✅未測球員頁現在的內容
背號 jersey_number✗✅球員頁現在標示「沒有」
頭貼 image_path✗✅同上
生日、身高、體重、國籍✗✅球員卡片可以做得更完整
隊長、合約起訖✗✅—
逐場先發名單✗✅解開戰術頁的瓶頸
逐場陣型✗✅同上
傷停✗✗端點名稱待查,見下

兩邊不是替代關係。 Understat 的 xG / xA / xGChain 是 SportMonks 這個方案沒測到的, 而背號、頭貼、逐場名單是 Understat 沒有的。球員頁最終會是兩邊合併。

待查 傷停:四個端點全部 404

/football/injuries、/football/sidelined、 /football/sidelined/teams/{id} 都回 「The requested endpoint does not exist」; ?include=player.sidelined 回 「The requested include 'sidelined' does not exist on Player」。

四個都是 404 不是 403 —— 照專案的規矩,那是路徑名稱的問題, 不是方案不含。最後一句最有價值:SportMonks 自己說 Player 上沒有這個 include。 要查它官方文件的正確名稱再試,不要再靠猜多燒幾輪。

不擋路 —— 英超的傷停走 FPL,西甲少這一項不影響戰術頁與球員頁。

探測腳本自己踩過的兩個坑

  • 取樣場次要用「確定已完賽」的。第一輪用 per_page=1 拿到賽季第一場,lineups/events/statistics 全空 —— 但那只是還沒踢。差一點就據此判定「這個方案給不了逐場名單」, 那會直接砍掉西甲戰術頁這條路。換成已完結的上一季取樣之後,兩個都有資料。
  • 判讀結論不要寫死在腳本裡。第一輪最後印的四行「判讀重點」是預先寫好的, 其中兩行跟實際結果相反(寫「聯賽都不在」「本季不在」,實際上都在)。 log 是下一個人唯一看得到的東西,寫死的結論會直接誤導他。 現在改成依實際結果產生,而且「無法判定」要明講是無法判定。

四、已經可以做,只是文件說還不行

今天就能動

已完成 進球子類型:十二碼與烏龍球

接手文件寫「description 還沒集滿,不要猜一個對照表寫死」。 那是舊的,已經改掉 —— 10 場 30 顆進球裡出現三種代碼, 而且我用名單核對過:O 那一顆是 Lindelöf(維拉)踢進自家門, 分算給 Brighton,確定是烏龍球;P 是十二碼。

單場分析頁的進球時間軸已經上線(賽後分頁的第一張卡):分鐘、射手、助攻、 累積比分,十二碼與烏龍球各有標籤。烏龍球會同時標出「這球算給誰」與 「踢進去的是哪一隊的人」—— 那兩件事不一樣,少標一個讀者就會以為我們記錯隊。

守住的界線 —— 沒見過的代碼一律不給分類,原碼留在 kindRaw。 測試會拿正式資料檢查有沒有第四種代碼,有的話就紅,逼下一個人先核對再放行。
沒做的 —— 球隊頁的進球時間分布面板。本季只有 10 場, 拿這種樣本畫分布會誤導人,等累積到半季再說。

六、模型本身

最難的一項

要工 英超模型仍然輸給市場 0.0025

RPS 0.2076 對收盤盤口的 0.2051。已經量過而沒通過的特徵:近五戰狀況、 近五戰進失球、歷來交手淨勝球 —— 三個都在雜訊範圍內,係數維持 0。

還沒試過、而且資料已經有的方向:進球情境(Understat 的五類 xG, 兩個聯賽都有了)、賽程密度(從賽程表就算得出來)、 傷停(等快照累積)。

規矩不變 —— 調參與驗收用不同賽季,改善要大過成對比較的標準誤, 照 npm run tune:form 的做法。沒通過就誠實寫在模型頁上,不要偷偷放進去。

八、不做的事

同樣重要

這些請不要做

  • 單一進球的球員級「進球方式」 —— Understat 給的是球隊整季摘要, 把某一類掛到某位球員的某一顆球是我們沒有的資料。球員逐球表不要加那一欄。
  • 把沒通過驗收的特徵放進模型 —— 近五戰與交手紀錄的係數是 0, npm test 有一條專門守著。直覺上該有用不是理由。
  • 大量爬網站 —— 靜態檔下載沒問題,官方進球事件是零額外請求。 一場一個請求的做法先不要做。
  • 為了畫面好看補測試資料 —— 西甲賽後快照現在是 0/11, 那是因為本機沒有金鑰。要真實數字就在有 Secret 的 runner 上跑,不要寫假資料進正式快取。
  • 拿賽後重建的模型冒充賽前預測 —— 沒有賽前快照的場次, prediction 就該是 null。
