# 進球細節:規格、排版與 AI 助手提示詞

> 目標:球隊詳情頁能回答「這一季進了幾球、對哪一隊進的、誰進的、誰助攻、
> 先發還是替補進的、第幾分鐘進的」。
>
> 分兩階段。**階段一先做**(一次下載就拿到兩季完整資料),
> 階段二再補(要一場一場打官方端點,慢慢拓)。
>
> 這份文件的用途:把「需要連外網、需要時間」的抽取工作分出去給 AI 助手做,
> 抽完的結果交回來,對照與前端由本專案接手。

## 二、階段一的輸出規格

每季一個檔:`epl/data/raw/fpl/{season}-goals.json`

```json
{
  "_season": "2025-26",
  "_source": "https://raw.githubusercontent.com/vaastav/Fantasy-Premier-League/master/data/2025-26/gws/merged_gw.csv",
  "_generatedAt": "2026-08-25T00:00:00Z",
  "_counts": {
    "csvRows": 29758,
    "records": 1042,
    "goals": 1116,
    "assists": 812,
    "ownGoals": 41,
    "unmatchedNames": 0,
    "scoreMismatches": 0
  },
  "records": [
    {
      "code": "223340",
      "team": "ARS", "opp": "COV", "home": true,
      "round": 1, "date": "2025-08-15",
      "min": 90, "start": true,
      "g": 1, "a": 0, "og": 0, "pm": 0
    }
  ]
}
```

欄位定義:

| 欄位 | 意義 | 型別 |
|---|---|---|
| `code` | 球員代碼。**取自 `players_raw.csv` 的 `code` 欄,不是 `element`** | 字串 |
| `team` / `opp` | 三碼隊伍代碼(ARS/COV/…) | 字串 |
| `home` | 該球員的球隊是否主場 | 布林 |
| `round` | 第幾輪 | 整數 |
| `date` | 開賽日期(從 `kickoff_time` 取 `YYYY-MM-DD`) | 字串 |
| `min` | 該場上場分鐘 | 整數 |
| `start` | 是否先發(`starts == 1`) | 布林 |
| `g` / `a` / `og` / `pm` | 進球 / 助攻 / 烏龍球 / 十二碼未進 | 整數 |

**只輸出 `g + a + og + pm > 0` 的列。** 29,758 列裡絕大多數是 0,全存會讓檔案
從 100 KB 變成 6 MB,而多出來的那些列一個問題也回答不了。

## 三、三個對照陷阱(做錯了不會報錯,只會靜靜給出錯的答案)

### 1. `element` 是「每一季重新編號」的,`code` 才是跨季穩定的鍵

`merged_gw.csv` 的 `element` 是那一季的 FPL 內部編號。
同一位球員在 2024-25 是 328、在 2025-26 可能是 412。
本專案的球員鍵是 `players_raw.csv` 的 **`code`**(Raya 在兩季都是 `154561`)。

→ **必須用同一季的 `players_raw.csv` 建 `element → code` 對照表。**

### 2. `opponent_team` 是「每一季重新編號」的隊伍 id

FPL 的隊伍 id 是該季 20 隊按英文名排序給的 1~20。
2025-26 的 `3` 是 Burnley;2024-25 的 `3` 是別隊(那季沒有 Burnley)。

→ **必須用同一季的 `teams.csv` 建 `id → short_name` 對照表。**
已驗證 `short_name` 與本專案的隊伍代碼 20 隊完全一致,可以直接用。

### 3. `name` 欄的格式在不同賽季不一樣

較早的賽季用 `First_Second_id` 這種底線格式,較新的用 `First Second`。
**不要用名字當鍵。** 名字只在對不上 `element` 時拿來人工核對。

## 四、自我檢查(請務必跑,並把結果寫進 `_counts`)

1. **對不上的 `element`**:每一列的 `element` 都要在該季的 `players_raw.csv`
   裡找得到。找不到就記進 `unmatchedNames`,並在報告裡列出前 10 個名字。
   正常情況這個數字應該是 **0**。

2. **比分核對**:對每一場比賽,
   `該隊球員 goals_scored 總和 + 對手球員 own_goals 總和` 必須等於該隊的實際比分
   (`team_h_score` / `team_a_score`)。
   對不上的場次數記進 `scoreMismatches`,並列出前 5 場。
   **正常情況應該是 0** —— 本專案已用 2026-27 第 1 輪驗證過這條規則成立
   (29 顆球員進球 + 1 顆烏龍球 = 賽果總和 30)。

3. **總數合理性**:一季英超約 1,000~1,200 顆進球。
   `_counts.goals` 明顯偏離這個範圍就是哪裡錯了,先別交,回頭查。

## 五、排版規格(球隊詳情頁)

在「教練」區塊之後、「開季賽程」之前,新增一段 `<h2>進球來源</h2>`,
內含四個面板。**標了「階段二」的面板在階段一先不做,不要放空殼。**

### 面板 1 — 對手分佈(階段一)

橫向長條,一列一個對手,依進球數排序。
每一列同時顯示「對他進幾球 / 被他進幾球」,用兩條反向的條。

- 條的顏色:本隊用本隊的 `chartColor`,對手用中性灰(`--ink-3`)。
  不要用對手的隊色 —— 20 隊一起出現時會變成彩虹,反而看不出重點。
- 沒交手過的隊伍不列(升班馬)。
- 下方一行說明:資料涵蓋哪一季、共幾場。

### 面板 2 — 進球榜與助攻榜(階段一)

兩欄並排的表格,各取前 8 名。欄位:球員、進球(或助攻)、每 90 分鐘、
先發/替補進球拆分。

- 「每 90 分鐘」要標明分母是上場分鐘,不是出賽場次。
- 出場不足 450 分鐘的球員,per-90 欄顯示 `—` 而不是一個會誤導人的大數字
  (這是本專案既有的 `QUALIFY_MINUTES` 規則,沿用)。

### 面板 3 — 先發 vs 替補(階段一)

一組對照數字:先發進球 N 球(佔 x%)、替補進球 M 球(佔 y%)。
下方一句話說明替補進球佔比的聯盟平均是多少,讓讀者知道這隊算高還是低。

### 面板 4 — 進球時間分布(**階段二**)

橫軸切成 6 段(0-15、16-30、31-45、46-60、61-75、76-90+),
縱軸是進球數與失球數。加時與傷停併入該半場的最後一段。

需要官方 events 的 `clock`,階段一做不到 —— **階段一不要放這個面板,
也不要放「資料準備中」的佔位**,沒有就是沒有。

### 共通規則

- 每個面板都要標明**資料涵蓋哪些賽季**。兩季完整、本季只有幾輪,
  這件事必須寫在畫面上,不能讓讀者自己猜。
- 「進球方式(運動戰/角球/任意球)」**不做也不要留欄位**。
  免費資料源沒有,留一個永遠空白的欄位比不做更糟。

## 七、提示詞 A —— 階段一:逐輪進球助攻抽取

### 任務

從公開的 FPL 資料鏡像抽取英超兩個賽季的**逐場進球與助攻紀錄**,
產出兩個 JSON 檔。

### 輸入(全部公開,不需要金鑰)

基底網址:`https://raw.githubusercontent.com/vaastav/Fantasy-Premier-League/master/data`

每個賽季(`2024-25`、`2025-26`)要下載三個檔:

```
{base}/{season}/gws/merged_gw.csv     逐輪 × 逐球員(主檔)
```

2. **`opponent_team` 也是每季重新編號**(1~20,依該季 20 隊英文名排序)。
   → 用**同一季**的 `teams.csv` 建 `id → short_name` 對照表。
   `short_name` 就是我要的三碼代號(ARS、LIV、MUN…),直接用,不用再轉。

3. **不要用 `name` 欄當鍵。** 它的格式在不同賽季不一樣(有的用底線串接 id)。
   名字只在對不上時拿來人工核對。

### 輸出格式(請嚴格照這個結構)

檔名 `{season}-goals.json`,例如 `2025-26-goals.json`:

```json

    { "code": "223340", "team": "ARS", "opp": "COV", "home": true,

```

- `opp`:對手三碼代號

**只輸出 `g + a + og + pm > 0` 的列。** 絕大多數列全是 0,

## 八、提示詞 B —— 階段二:官方進球事件抽取

> 階段一交付並驗證通過之後再開始。同樣把 `---` 之間整段複製給 AI 助手。

---

### 任務

從英超官網後端抽取**每一顆進球的事件明細**(誰進的、誰助攻的、第幾分鐘、
當下比分),產出一個 JSON 檔。

### 端點(免金鑰,但必須帶 header)

```
基底  https://footballapi.pulselive.com/football
Header  Origin: https://www.premierleague.com
        Referer: https://www.premierleague.com/
        User-Agent: <隨便一個正常的瀏覽器 UA>
```

三步:

```
1. GET {base}/competitions/1/compseasons
   → content[] 裡每筆有 id 與 label(例如 "English Premier League Season 2026/2027")

2. GET {base}/fixtures?comps=1&compSeasons={seasonId}&statuses=C&page=0&pageSize=100&sort=desc
   → content[] 是已完賽的比賽,每筆有 id 與 teams[0..1].team.{id,name}
   → 要翻頁把整季 380 場拿齊

3. GET {base}/fixtures/{fixtureId}
   → 單場詳情,我要的是 events 與 teamLists
```

### 事件的實際長相(我已經實測過,不用重新摸索)

```json
{ "id": 183587, "personId": 72371, "teamId": 4, "assistId": 49293,
  "clock": { "secs": 60, "label": "01'00" }, "phase": "1",
  "type": "G", "description": "G",
  "score": { "homeScore": 0, "awayScore": 1 } }
```

型別代碼:`G` 進球、`B` 出牌(`description` 是 `Y`/`R`)、`S` 換人
(`description` 是 `ON`/`OFF`)、`PS`/`PE` 半場開始與結束。

**注意:`type` 是代碼不是英文字。** 不要用 `/goal/i` 去比對字串 ——
我第一次就是這樣誤判成「沒有進球事件」的。

### 我特別想知道的一件事

`G` 事件的 `description` 在一般進球時是 `"G"`。
**請幫我確認十二碼進球與烏龍球的 `description` 是什麼**
(掃過整季所有 `G` 事件,把出現過的 `description` 值全部列出來與各自的次數)。
這決定了我能不能把「一般進球 / 十二碼 / 烏龍球」分開顯示。

### 禮貌抓取

這是別人的端點,而且沒有公開文件:

- 每個請求間隔 **至少 300ms**,不要並發超過 2 條
- 失敗重試最多 3 次,指數退避(1s / 2s / 4s)
- 連續失敗 10 次就停下來回報,不要硬跑完
- 一季 380 場大約 2~3 分鐘,不趕時間

### 輸出格式

檔名 `{season}-events.json`:

```json
{
  "_season": "2026-27",
  "_seasonId": 841,
  "_source": "https://footballapi.pulselive.com/football/fixtures/{id}",
  "_generatedAt": "<ISO 8601>",
  "_counts": {
    "fixtures": 380, "fetched": 380, "failed": 0,
    "goals": 1102, "goalsWithAssist": 731,
    "descriptions": { "G": 1050, "P": 38, "O": 14 }
  },
  "people": {
    "72371": { "name": "Bryan Mbeumo", "teamId": 4 }
  },
  "fixtures": {
    "FUL|CHE": {
      "fixtureId": 128932,
      "home": "FUL", "away": "CHE",
      "goals": [
        { "personId": 72371, "assistId": 49293, "teamId": 4,
          "minute": 1, "label": "01'00", "phase": "1",
          "kind": "G", "hs": 0, "as": 1 }
      ]
    }
  }
}
```

- `people` 是 `personId → { name, teamId }` 的字典,
  **從各場的 `teamLists` 收集**(裡面每個球員有 `id` 與 `name`)。
  這是我把官方球員對回自己資料庫的唯一線索,**一定要附**。
- `minute`:從 `clock.label` 取分鐘數。`45+3'00` 算 45,
  但 `label` 原文也要保留在 `label` 欄。
- `kind`:直接放 `description` 的原值,不要自己翻譯。
- 隊伍代碼:`teams[].team.name` 是全名(例如 "Fulham"),
  請一併輸出 `_teams` 字典(`teamId → 官方全名`),我這邊自己對照三碼代號。

### 自我檢查

1. 每一場的 `goals` 筆數,要等於該場最終比分的總和
   (從最後一筆 `PE` 事件的 `score` 取,或從 fixture 的 `teams[].score`)。
   對不上的場次列出來 —— 通常是烏龍球記在哪一隊的問題,我要知道細節。
2. `_counts.failed` 不是 0 的話,把失敗的 fixtureId 列出來。

### 回報時請一併告訴我

- `_counts` 全部
- **`description` 出現過哪些值、各幾次**(這是我最想知道的)
- 比分核對對不上的場次明細
