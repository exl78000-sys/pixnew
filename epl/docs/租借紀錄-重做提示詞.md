## 三、**最重要的一件事:請給穩定的球員 id**

目前每一筆只有球員的**名字字串**,而名字是最不可靠的鍵:

- 同一份交付裡就有不一致:`Ramon Terrats`(2025-26)與 `Ramón Terrats`(2026-27)
- 重音有無、拼法差異會讓比對失敗:`Raul de Tomas` / `Raúl de Tomás`、
  `Cenk Ozkacar` / `Cenk Özkacar`、`Sergi Canos` / `Sergi Canós`
- 英超光是同姓的就有 15 組(Martínez 兩位、Wilson 三位),只比姓氏會**對到錯的人**

**如果每一筆能附上 Transfermarkt 的球員 id(或 FotMob 的球員 id),
名字比對這個問題就整個消失了。** 這是這次重做裡投報比最高的一項 ——
比修那 7 筆重要得多,因為它讓往後每一次交付都不必再處理拼法問題。

欄位加成這樣就好:

```json
{
  "season": "2025-26",
  "league": "LaLiga",
  "player": "Ramón Terrats",
  "playerId": { "transfermarkt": 471460 },
  "parentClub": "Getafe",
  "loanClub": "Espanyol",
  "date": "2025-07-01",
  "source": "https://..."
}
```

同樣的道理也適用於球隊 —— 有 `clubId` 更好,但球隊名的問題比球員小得多,
不強求。

## 四、`league` 欄位的歸檔規則要講清楚

現在同一個欄位有兩種用法:

- `Andrés García / Aston Villa → Getafe` 標 `Premier League`(母隊的聯賽)
- `Sebastián Boselli / River Plate → Alavés` 標 `LaLiga`(目的地的聯賽)
- `Quilindschy Hartman / Burnley → Espanyol` 標 `LaLiga`(母隊在英冠)

三種都能理解,但混在同一個欄位裡就沒辦法拿它當索引。**請二選一並寫進檔案的
`scope` 裡**,或乾脆拆成 `parentLeague` 與 `loanLeague` 兩個欄位(這樣最清楚)。

## 六、交付格式

跟上一份一樣即可,加上第三節的 `playerId` 與第四節的聯賽欄位。

## 七、幾條規則

1. **不准編**。抽不到就少一筆、少一個賽季,並在檔案裡寫明抽不到什麼。
   一個看起來完整但其實是推出來的賽季,比缺一個賽季糟得多。
2. **不要從別的賽季推導**。這正是 2024-25 那批出問題的原因。
3. **逐筆帶來源網址**。交付時附上抓取日期。
4. **不確定的標出來**,不要靜靜猜一個值。

## 八、我這邊會怎麼驗(所以你可以自己先跑一次同樣的邏輯)

收到之後會跑 `npm run loans:verify`,拿三份彼此獨立的資料核對每一筆:

1. **逐季聯賽成員資格** —— 母隊當季在不在它宣稱的那個聯賽
   (這條就是抓到 Leeds 那 6 筆的)
2. **逐季出賽分鐘** —— 宣稱夏窗被租出英超的人,當季不該有大量英超出賽
   (夏窗門檻 450 分鐘、冬窗 1800;冬窗離隊前本來就打了半季,不能用同一個門檻)
3. **目的地聯賽的逐季球員** —— 他當季到底在哪一隊
   (這條抓到 Alavés 那一批)

另外還有兩道:

- **年份平移偵測** —— 同一組(球員+母隊+租借隊)月日相同、只差年份的一律擋下
- **區塊連坐** —— 同一個(賽季+目的地)裡只要有紀錄被證明是錯的,**剩下的整批不採用**

判定分四級,只有前兩級會被發布:

| 等級 | 意思 |
|---|---|
| `confirmed` | 有獨立來源**正面確認**他當季在那一隊 |
| `consistent` | 查得動的檢查都沒有矛盾,但沒有正面確認 |
| `contradicted` | 與獨立資料矛盾 —— 不發布 |
| `unverifiable` | 沒有任何獨立資料涵蓋得到 —— 不發布 |

上一份的成績是 confirmed 19 / consistent 98。
**有 `playerId` 之後 confirmed 的比例會明顯上升**,因為比對不會再卡在名字上。
