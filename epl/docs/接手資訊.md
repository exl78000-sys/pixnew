## 現在長什麼樣子

**網站**:導覽列分兩組,中間有分隔線 ——

```
左(跨聯賽,切換聯賽時不換)   足球知識、歐冠
右(這個聯賽)                {英超|西甲}首頁、實時戰況、英格蘭盃賽*、分析▾
分析組(進到組裡才出現子分頁)  球隊、戰術、球員、動態、模型驗證
                            * 英格蘭盃賽只在英超側,es1 的 open 清單刻意沒有它
```

清單在 `core.js` 的 `SITE_PAGES`(左)與 `PAGES`(右)。
**同一頁兩邊都放的話導覽列會出現兩個一樣的分頁**,左右各一個,而且不會報錯(踩過,測試補了一條)。

- 分頁模式(`web/*.html`)—— **GitHub Pages 實際部署的是這個**
- 單檔模式(`dist/warroom.html`,19.33 MB)—— 所有資料內嵌,離線可開

## Obsidian vault(2026-08-28 新增)

`npm run obsidian` 把兩個聯賽的資料集攤成互相連結的 Markdown,輸出到 `epl/vault/`。
2,101 則筆記:球隊 40、球員 1,299、比賽 760、聯賽首頁 2。

**這是產物,比照 `dist/`。** `.gitignore` 忽略 `epl/vault/*`,
但**留了一個例外**:`!epl/vault/我的筆記/`。那個資料夾是使用者手寫的,
產生器永遠不碰、git 也要留著。產生器只清空自己產生的聯賽資料夾,不做整個 vault 的 rm。

**寫檔前有兩道守門,不通過就中止而且一個檔案都不寫:**

1. **沒有兩則筆記同檔名。** Obsidian 的 `[[連結]]` 是**跨資料夾用檔名**解析的,
   同名會讓連結靜靜指到其中一個,不會有任何地方報錯。
2. **每個 `[[連結]]` 都指得到筆記。** 6,299 條連結逐條查。
   指不到的話在 Obsidian 裡點下去是空白新檔,看起來像資料漏了。

兩道都實測過會擋(塞一個假連結進去,確認中止且沒寫檔)。

**三個「不要照抄資料集」的地方,每一個都有理由:**

- **已完賽場次不放預測數字。** `fixtures.json` 的 `prediction` 在已完賽場次是
  **建置時重算**的 —— `build.mjs` 的 `trainMatches = [...history, ...curPlayed]`,
  模型已經看過那場結果。走查回測(真正的賽前預測)只涵蓋 2025-26,本季沒有賽前快照。
  照搬就是拿賽後重建冒充賽前預測。未賽場次的預測是真的,照放。
- **同名球員不合併。** 以 fullName 當檔名,1,299 人裡 15 組撞名:13 組跨聯賽
  (多半是轉會的同一人,例如 Rashford 上季在巴薩)、2 組是西甲內部的不同人。
  逐一查過 sportmonksId:**兩份資料源從來沒有在同一個名字上同時給出 id,0 組可核對**。
  所以各自成篇、檔名加隊碼、筆記上寫明無法核對(鐵則五)。
- **沒有出賽紀錄不列一整排 0。** 英超有 56 人上季 `minutes=0`,
  但那個 0 分不出「在英超但沒上場」與「當季不在英超」—— 外借到別的聯賽一樣是 0。
  換成把這件事講清楚。

西甲的 `players.json` 是**一人一季一筆**,966 筆裡 266 組是同一個 Understat id 的
跨季重複,要先按 id 去重(700 人)再產生,不然會產生兩個同名檔案。

另外 85 名西甲球員的隊碼是 MLL / OVI / GIR ——上季在西甲、本季不在,

## GitHub Actions（本機優先模式）

| 工作流程 | 頻率 | 做什麼 |
|---|---|---|
| `epl-live.yml` | 手動 | 抓資料 → `npm test` → build → snapshot → bundle → 部署 Pages → 回寫資料 |
| `epl-matchday.yml` | 手動 | 遠端備援；需要時才進場用 **job 內迴圈**每 2 分鐘更新 |
| `laliga-matchday.yml` | 手動 | 遠端備援；SportMonks 西甲 `livescores/inplay`，快照有變才 build／提交 |
| `probe-apis.yml` | 手動 | 資料源探測(沙箱連不到外網,靠這個實測) |

目前改用本機 `npm run local:watch`：英超每 60 秒更新，西甲在有本機
`SPORTMONKS_TOKEN` 時每 120 秒更新，**不會推送**。累積完成後再一次
`git push`，最後到 Actions 手動執行 `epl-live.yml` 發布 Pages。這樣不會被 GitHub
runner 的長時間輪詢或排程佇列卡住。

準備發布前執行 `npm run local:sync`，會把英超與西甲即時快照寫回本地並重建兩聯賽資料集；
它最多對西甲即時端點請求 2 次，不會補抓整季或賽後大批量資料，也不會自行提交。

## 最近幾次改動的脈絡(免得你把它們改回去)

**備援的方案限制不再冒充「整季拿不到」(2026-08-28)**:西甲賽後資料由 SportMonks
發布 16/20,但 8/25~8/27 剛完賽那 4 場(含 Real Madrid vs Real Sociedad)的頁面
寫著「本站使用的資料源方案不含本賽季…在換成涵蓋本賽季的方案之前,球隊統計、
正式陣容、事件與球員評分都不會出現」—— 而隔壁 16 場那些東西全都在。

原因是 `build-laliga.mjs` 的判斷還停在「API-Football 是唯一來源」的年代:
只要還有場次沒發布,就把備援的 `blocked` 傳到前端。SportMonks 接成主要來源之後
沒跟著改。同一個地方還有一行摘要把發布數**寫死成 0**(`完整賽後資料：0/20`),
而摘要正是寫文件的人拿來抄的數字。

現在分成兩個欄位,兩者最多只有一個非 null:

- `blocked` —— **主要來源一場都發不出來**才給(`reportCount === 0`)。這一季真的拿不到。
- `backupBlocked` —— 主要來源可用、備援補不了缺口。缺口照實說是「還沒抓到」,
  同時交代備援為什麼補不了。

`page-analysis.js` 的 `missingReportCard()` 因此有**三種**狀態不是兩種。
`npm test` 加了四條守著,其中「主要來源已發布場次時 blocked 必須是 null」
拿修好前的產物跑會紅。坑本身寫進 `CLAUDE.md` 陷阱表。


**歐冠(2026-08-27~28)**:來源是 football-data.org(`npm run ucl`,需 `FOOTBALL_DATA_TOKEN`),
2024-25 與 2025-26 完整、2026-27 只有 FotMob 人工交付的抽籤結果。三件不要改回去的:

- **PK 場的比分不是 `fullTime`。** 上游的 `fullTime` 是**累加值**
  (`regularTime + extraTime + penalties`),2025-26 決賽直接印會變成「PSG 5-4 Arsenal」,
  實際是 1-1、PK 4-3。轉換在 `lib/adapters/football-data-ucl.mjs` 做完了。
- **FotMob 的比賽網址順序不是主客。** `/matches/{甲}-vs-{乙}/` 只有一半對得上,
  主客要看 `home` / `away` **欄位**(378 場全對)。照 slug 推會得到完全錯誤的結論。
- **名字與隊徽走 `ucl-teams.json`,不要改回去查目前聯賽的 `clubs.json`。**
  兩份 clubs 的隊碼交集是 0,查了的話同一支球隊在英超頁叫 `Barça`、在西甲頁叫
  `FC Barcelona`,隊徽也只出現一半。這一份由 `lib/ucl.mjs` 的 `uclTeamAssets()` 產出,
  兩個 build 各呼叫一次、逐位元組相同。前端**先登錄它、再登錄本聯賽的**
  (registerTeams 是逐欄位覆蓋,反過來會蓋掉配色與 chartColor)。測試守著這兩件事。

**英格蘭盃賽(2026-08-27)**:足總盃 + 聯賽盃,SportMonks。
對手隊徽在 `data/manual/crests-cups.json`(**用 SportMonks team id 當鍵**,
同一張圖只存一份;掛在每個位置上的話 cups.json 會從 741 KB 變成 5223 KB)。
對手的聯賽層級在 `data/manual/team-tiers.json`(openfootball,免費)。
**隊名正規化只去字尾的 FC/AFC** —— 字首的 AFC 是身分的一部分,
去掉的話第九級的 `AFC Liverpool` 會被對成英超的 Liverpool(踩過兩次,靠 nearMisses 抓到)。

**實時戰況頁:完賽三天內留在最上面**(`RECENT_MS = 3 * 24 * 3600 * 1000`)。
比完就掉到「已完賽」區塊的話,週末打完隔天想回頭看要往下捲很久。

**人工整理外電是累積的(2026-08-28)**:`news-curated.json` 是**收件匣**(協作方每次交付的整份檔案,
一份只涵蓋一週),由 `npm run news:merge` 併進 `news-curated-archive.json` 這個**檔案庫**。
直接讀收件匣的話,下一次交付會把上一週整批蓋掉而且**不會有任何地方報錯**。
build 讀的是**檔案庫疊上收件匣**(同一個 id 以收件匣為準)。
涵蓋範圍在動態頁上照實講,**含斷檔**——只印頭尾的話「8/22~9/11」看起來像連續 21 天,
