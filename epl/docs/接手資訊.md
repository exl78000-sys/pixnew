## 排程(GitHub Actions)

| 工作流程 | 頻率 | 做什麼 |
|---|---|---|
| `epl-live.yml` | 每 12 小時 | 抓資料 → `npm test` → build → snapshot → bundle → 部署 Pages → 回寫資料 |
| `epl-matchday.yml` | 每 15 分鐘檢查 | 有比賽才進場,用 **job 內迴圈**每 2 分鐘更新 |
| `probe-apis.yml` | 手動 | 資料源探測(沙箱連不到外網,靠這個實測) |

**為什麼比賽日要獨立一個工作流程**:GitHub 的 cron 是 best-effort,
實測設定 15 分鐘、實際間隔 28~78 分鐘(平均 46)。但 **job 內部的迴圈不受限制** ——
單一 job 最長 6 小時,迴圈裡的 sleep 是準的。所以 cron 只負責開場。

### 3. 官方進球事件的子類型(等資料累積)

十二碼與烏龍球的代碼還沒集滿。**不要猜一個對照表寫死** ——

累積到夠之後可以做:球隊頁的**進球時間分布**面板(規格已寫好,
在 `docs/進球細節-規格與提示詞.md` 第五節的「面板 4」),以及單場分析頁的進球時間軸。

### 4. 傷停特徵回測(約 60 天後)
`data/availability-history.json` 每天累積一筆。到 `backtestable: true`
(60 天)之後,比照 `npm run tune:form` 的做法量一次「缺了多少戰力」對 RPS 有沒有幫助。
**只有驗收段改善超過一個標準誤才進模型**,否則維持只當資訊顯示。

### 5. 補 216 名球員頭貼
提示詞已寫好:`docs/球員頭貼抓取-提示詞.md`。

### 6. 歐冠
`football-data.org` 免費方案含歐冠。**英國盃賽(足總盃、聯賽盃)不在免費方案裡** ——
這件事已經確認過,不要再花時間找。
需要 `FOOTBALL_DATA_TOKEN` secret(已設)。盃賽要另一套模型(加時、PK、兩回合),
不是把現有模型套上去就好。

## 使用者的長期要求(反覆講過,照做)

- 不要讓 LLM 自己猜數據或算結果
- MVP 不買昂貴的 Opta / StatsBomb 商業 API
- 設計快取,不要讓每個使用者直接打 Football API
- API key 不可放前端
- 先以免費 API 為主
- 比賽當下 10~15 分鐘更新可以接受;**沒比賽就不用頻繁**
- 先做英超、歐冠、英國盃賽
- **Web 為主**,iOS 很後期才考慮
- **先不要大量提取網站,怕被阻擋**
