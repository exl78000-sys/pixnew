## 現在長什麼樣子

**網站**:導覽列分兩組,中間有分隔線 ——

```
左(跨聯賽,切換聯賽時不換)   足球知識、歐冠

- 分頁模式(`web/*.html`)—— **GitHub Pages 實際部署的是這個**
- 單檔模式(`dist/warroom.html`,19.33 MB)—— 所有資料內嵌,離線可開

## 外電(2026-08-28 修)

**英超的 RSS 以前沒有任何流程在抓。** `laliga-news-daily.yml` 只抓西甲,

scripts/fetch-news.mjs 更新」。那支工作流程改名為「兩聯賽外電每日快取」,兩邊都抓。

抓完之後英超動態從 85 則變成 **130 則**(多出來的 45 則是 RSS)。

**兩個修掉的坑:**

1. `feeds.json` 裡叫「Sky Sports 英超」的那一筆,網址其實是 Sky News 的**綜合體育** feed。
   2026-08-28 抓回來的有拳擊(Baumgardner vs Dubois)與網球(US Open quiz),
   而它們會掛在動態頁上標成英超外電。換成 `skysports.com/rss/11661`,實測 20 則全是英超。
   **加來源時先抓一次看標題,不要只看名字。**
2. Sky Sports 的 pubDate 是 `... 19:00:00 BST`,`new Date()` 解不了這個時區縮寫,
   而原本的寫法直接 `.toISOString()` —— 整個來源的 15 則全部消失,
   只留下一行「✗ Invalid time value」。現在 `parseFeedDate()` 會補時區偏移,
   真的解不開就用抓取當天並把筆數報出來。

**沒有動的**:Guardian 把「Sports quiz of the week」放在自己的英超 feed 裡,
那是來源自己的分類,不是本站標錯。用關鍵字黑名單去殺會誤傷真文章,所以留著。

### 管線

```

**build 只讀 `loans-verified.json`,不讀收件匣。** 收件匣裡有已知是錯的紀錄。

### 判定分四級,不是通過/不通過

| 等級 | 意思 | 發布 |
|---|---|---|
| `confirmed` | 有獨立來源**正面確認**他當季在那一隊 | ✓ 19 筆 |
| `consistent` | 查得動的檢查都沒有矛盾,但沒有正面確認 | ✓ 98 筆 |
| `contradicted` | 與獨立資料矛盾 | ✗ 8 筆 |
| `block-suspect` | 同一批(賽季+目的地)裡有紀錄被證明是錯的 | ✗ 1 筆 |
| `unverifiable` | 沒有任何獨立資料涵蓋得到 | ✗ 5 筆 |

**等級要跟著資料走到畫面上。** 「有獨立來源確認」與「只是沒查到矛盾」對讀者的意義
不同,混成一句「有租借紀錄」就是把不確定性藏起來(鐵則四)。

### 核對器擋掉的三種東西

1. **母隊當季不在那個聯賽**(只在紀錄的 `league` 就是母隊聯賽時才查 ——
   英冠的 Burnley 把人租給西甲的 Espanyol 完全正常,不能拿英超成員資格去卡)。
2. **外借出英超卻有大量英超出賽分鐘**(夏窗門檻 450 分鐘、冬窗 1800 ——
   冬窗離隊前本來就打了半季,同一個門檻會誤判)。
3. **目的地聯賽的逐季球員把他放在別隊**(只有全名精確對上才敢判矛盾;
   姓氏推出來的配對只當參考 —— 英超光同姓的就有 15 組)。

**區塊連坐**:同一個(賽季 + 目的地)裡只要有紀錄被證明是錯的,剩下的整批不採用。
實測 6 筆「→ Alaves」有 5 筆其實在 Getafe,而交付檔裡「→ Getafe」的引進是 0 筆。

**不列入連坐的**:交付檔自己的重覆列(hygiene)。刪掉重覆就好,
不代表同一批的其他紀錄不可信 —— 不分這兩種的話測試會誤報。

### 我自己在這裡踩的坑

`data/raw/fpl/{季}-players.csv` **當季那一份裝的是上一季的數字**
(2026-27 的檔案裡 Raya 是 3330 分鐘,而本季只踢了 1 輪)。
第一版拿它當本季分鐘用,誣賴了四筆真紀錄。現在每份 CSV 用之前先自我檢查:
**進球總和要等於 `goals.json` 的該季總進球**,對不上就拒用。

另外兩個誤判也修掉了:租借**目的地**不必在那個聯賽(租到英冠是常態),
母隊的聯賽檢查只在紀錄的 `league` 就是母隊聯賽時才做。

## Obsidian vault(2026-08-28 新增)

`npm run obsidian` 把**全部**資料集攤成互相連結的 Markdown,輸出到 `epl/vault/`。
**5,675 則筆記、16,587 條連結、23 MB。**

| 資料夾 | 內容 |
|---|---|
| `英超/` | 27 隊・599 球員・1,520 場(本季 380 + 歷史 1,140)・23 教練 |
| `西甲/` | 29 隊・700 球員・760 場(本季 380 + 歷史 380)・20 教練 |
| `歐冠/` | 3 個賽季 + 378 場(含淘汰賽逐回合) |
| `英格蘭盃賽/` | 足總盃 + 聯賽盃・1,573 場 |
| `足球知識/` | 背號 12・位置角色 18・陣型 8 + 主題頁 |

球隊名冊取的是**聯集不是本季 20 隊**:英超 27(clubs.json)、西甲 29
(`data/manual/teams-la-liga.json`)。只認本季 20 隊的話,歷史比賽的對手會變成
沒有連結的純文字,而且 85 名西甲球員(MLL / OVI / GIR)連不到任何球隊筆記。
只有身分沒有賽季數據的球隊,筆記上直接寫明「本季不在這個聯賽」。

賽後報告與隊級進球明細**不另開筆記**,分別併進比賽筆記與球隊筆記 ——
它們是那則筆記的內容,不是獨立的東西。

歐冠與盃賽**不另開球隊筆記**:本站認得的球隊連回既有筆記,不認得的只印名字。
給每一隊開一則的話,認得的那幾支會跟聯賽球隊筆記變成兩個同名檔案,連結會指錯。

**這是產物,比照 `dist/`。** `.gitignore` 忽略 `epl/vault/*`,
但**留了一個例外**:`!epl/vault/我的筆記/`。那個資料夾是使用者手寫的,
產生器永遠不碰、git 也要留著。產生器只清空自己產生的聯賽資料夾,不做整個 vault 的 rm。

**寫檔前有兩道守門,不通過就中止而且一個檔案都不寫:**

1. **沒有兩則筆記同檔名。** Obsidian 的 `[[連結]]` 是**跨資料夾用檔名**解析的,
   同名會讓連結靜靜指到其中一個,不會有任何地方報錯。
2. **每個 `[[連結]]` 都指得到筆記。** 6,299 條連結逐條查。
   指不到的話在 Obsidian 裡點下去是空白新檔,看起來像資料漏了。

兩道都實測過會擋(塞一個假連結進去,確認中止且沒寫檔)。

**歷史場次有真正的賽前預測。** 走查回測(`data/backtest-matches.json` /
`data/backtest-laliga-matches.json`)的訓練資料只到該輪開賽前,那是真的賽前預測,
所以 2025-26 的場次照放,並標明它跟 `fixtures.json` 那份重算的不是同一個東西。

**我自己踩了一次跟陷阱表同類的坑,記在這裡。** 歐冠的 `et` 不是「延長賽後的比分」,
是**延長賽的增量**。2025-26 決賽 `final=[1,1]`、`ft90=[1,1]`、`et=[0,0]`、`pens=[4,3]`,
照 `et` 印會變成「0:0(PK 4:3)」——而且半場還印著 0:1,自己跟自己矛盾。
拿全部資料驗過:`final === ft90 + et` 在歐冠 378 場全部成立,而 `ft90` 有 372 場是 null,
所以**比分只能讀 `final`**。盃賽 1,444 場裡有 2 場上游自己加不回來,
那兩場照印 `final` 但在筆記上標明分段對不起來,不挑一個當答案。

**上游會把同一場掛在兩個階段。** 足總盃 2026-27 的
Aylesbury United vs Flackwell Heath 同時出現在 `Extra Preliminary Round` 與
`…Replays`,除了 id 以外每個欄位都一樣(而且首戰 2-3 有勝負,不可能有重賽)。
只合併「開球時間、比分、完賽狀態全部相同」的那種,真正的重賽日期不同、key 本來就不會撞。
合併掉的事實寫在筆記上,不靜靜吃掉。1,573 場裡只有這 1 組。

**空陣列不是「有值」。** 西甲教練的 `style` 是 `[]`,原本渲染成一列空的「風格註解」,
同時讓「上游沒有給」那份清單漏列風格 —— 兩個地方一起錯。
現在「有沒有值」只有一個 `hasValue()`,所有地方共用。

**清空範圍是從這次要寫的路徑推出來的**,不是寫死聯賽資料夾。
加了歐冠/盃賽/足球知識之後,寫死的話那三個永遠不會被清,舊筆記會留著而且不會報錯。
產生器另外有一道斷言:如果它想寫進 `我的筆記/` 就中止。

**三個「不要照抄資料集」的地方,每一個都有理由:**

- **已完賽場次不放預測數字。** `fixtures.json` 的 `prediction` 在已完賽場次是
  **建置時重算**的 —— `build.mjs` 的 `trainMatches = [...history, ...curPlayed]`,
  模型已經看過那場結果。走查回測(真正的賽前預測)只涵蓋 2025-26,本季沒有賽前快照。
  照搬就是拿賽後重建冒充賽前預測。未賽場次的預測是真的,照放。
- **同名球員不合併。** 以 fullName 當檔名,1,299 人裡 15 組撞名:13 組跨聯賽
  (多半是轉會的同一人,例如 Rashford 上季在巴薩)、2 組是西甲內部的不同人。
  逐一查過 sportmonksId:**兩份資料源從來沒有在同一個名字上同時給出 id,0 組可核對**。
  所以各自成篇、檔名加隊碼、筆記上寫明無法核對(鐵則五)。
- **沒有出賽紀錄不列一整排 0。** 英超有 56 人上季 `minutes=0`,
  但那個 0 分不出「在英超但沒上場」與「當季不在英超」—— 外借到別的聯賽一樣是 0。
  換成把這件事講清楚。

西甲的 `players.json` 是**一人一季一筆**,966 筆裡 266 組是同一個 Understat id 的
跨季重複,要先按 id 去重(700 人)再產生,不然會產生兩個同名檔案。

另外 85 名西甲球員的隊碼是 MLL / OVI / GIR ——上季在西甲、本季不在,
所以沒有球隊筆記。那一列不省略,直接寫「本季不在西甲,沒有球隊筆記」。

## 最近幾次改動的脈絡(免得你把它們改回去)

**備援的方案限制不再冒充「整季拿不到」(2026-08-28)**:西甲賽後資料由 SportMonks
發布 16/20,但 8/25~8/27 剛完賽那 4 場(含 Real Madrid vs Real Sociedad)的頁面
寫著「本站使用的資料源方案不含本賽季…在換成涵蓋本賽季的方案之前,球隊統計、
正式陣容、事件與球員評分都不會出現」—— 而隔壁 16 場那些東西全都在。

原因是 `build-laliga.mjs` 的判斷還停在「API-Football 是唯一來源」的年代:
只要還有場次沒發布,就把備援的 `blocked` 傳到前端。SportMonks 接成主要來源之後
沒跟著改。同一個地方還有一行摘要把發布數**寫死成 0**(`完整賽後資料：0/20`),
而摘要正是寫文件的人拿來抄的數字。

現在分成兩個欄位,兩者最多只有一個非 null:

- `blocked` —— **主要來源一場都發不出來**才給(`reportCount === 0`)。這一季真的拿不到。
- `backupBlocked` —— 主要來源可用、備援補不了缺口。缺口照實說是「還沒抓到」,
  同時交代備援為什麼補不了。

`page-analysis.js` 的 `missingReportCard()` 因此有**三種**狀態不是兩種。
