# 歐冠球隊隊徽 —— 交付提示詞

給協作助手。目標:把歐冠頁與 Obsidian vault 裡「只有名字、沒有隊徽、點不進去」的
40 支球隊補上隊徽。

---

## 背景(先讀,決定了幾個不能自己改的規則)

本站的歐冠資料有三季(2024-25、2025-26、2026-27),三季合計 **54 支不重複球隊**,
但只有 **13 支**是本站兩個聯賽(英超、西甲)本來就認得的 ——
其餘 41 支在畫面上只有名字,沒有隊徽也點不進去。

隊名對照**已經做完了**,不用重做:下面那張表是拿倉庫裡既有的兩份資料對出來的
(`web/data/ucl.json` 的 football-data.org 隊名 × `data/manual/fotmob-ucl-*.json`
的 FotMob 隊名),41 支裡 40 支對得上。**你要做的只有抓圖與存檔。**

---

## 要做的事

抓下面 40 支球隊的隊徽,縮成 64px PNG,寫成
`epl/data/manual/crests-ucl.json`。

### 抓圖來源

FotMob 的圖片 CDN,用表裡的 FotMob id:

```
https://images.fotmob.com/image_resources/logo/teamlogo/{fotmobId}.png
```

**抓取禮貌(使用者明確要求過,不可以放寬):**

- 單線,不要並發
- 每次請求間隔 **≥ 1.2 秒**
- 只抓表裡這 40 個 id,**不要為了「順便」多抓任何東西**
- 一次跑完;失敗的記進 `failed`,不要無限重試

### 輸出格式

比照倉庫裡既有的 `epl/data/manual/crests-cups.json`,**格式要完全一致**:

```json
{
  "_note": "歐冠球隊隊徽,key 是 FotMob 的 team id(不是本站隊碼)。本站兩個聯賽認得的球隊走 clubs.json / teams-la-liga.json,不放這裡。來源:FotMob image_resources。",
  "crests": {
    "8593": "data:image/png;base64,iVBORw0KGgo...",
    "8524": "data:image/png;base64,..."
  },
  "sources": {
    "8593": { "name": "Ajax", "url": "https://images.fotmob.com/image_resources/logo/teamlogo/8593.png" }
  },
  "failed": {},
  "retrievedAt": "<ISO 8601>",
  "width": 64
}
```

**key 用 FotMob team id,不要用隊名。** 隊名在不同來源寫法不同
(Praha / Prague、Olympiakos / Olympiacos),拿它當鍵一定會對錯。

**同一張圖只存一份。** 盃賽那邊踩過:把圖掛在每個出現位置上,
`cups.json` 會從 741 KB 變成 5223 KB。

縮圖可以直接用倉庫裡現成的 `epl/scripts/lib/png.mjs`
(`decodePNG` / `resizeRGBA` / `encodePNG`),`scripts/fetch-cup-crests.mjs`
就是這樣做的,照抄那支的做法最省事。

## 交付時要一起附上的東西

1. **`crests-ucl.json`** 本身。
2. **一份逐隊清單**:哪幾支抓到、哪幾支失敗、失敗的 HTTP 狀態碼是什麼。
3. **實際請求次數**與**總耗時**(用來確認有守間隔)。
4. 如果有任何一支你覺得抓到的圖「看起來不像那支球隊」,**直接說**,
   不要自己換一個來源補上。寧可少一張。

---

## 幾條不可以違反的規則

這個專案的賣點不是功能多,是**每個數字與每張圖都查得到出處**。

1. **不准編**。抓不到就記進 `failed`,不要用別的球隊的圖、不要用佔位圖、
   不要自己畫一個。
2. **不要擴大抓取範圍**。只有表裡那 40 個 id。不要順手抓球員照、
   不要抓別的賽季、不要抓聯賽頁。
3. **key 一定是 FotMob team id**,不是隊名也不是本站隊碼。
4. **失敗要留下痕跡**。`failed` 裡要有 id、隊名、HTTP 狀態,
   下一個人才知道是暫時失敗還是那個 id 根本沒圖。
5. **不要動倉庫裡其他任何檔案。** 只產出 `crests-ucl.json` 一個檔。
   接到網站與 vault 的那一步由我這邊做。

## 驗收標準(我收到之後會這樣檢查)

- `crests` 的 key 全部落在上表那 40 個 id 裡,沒有多的
- 每個值都是 `data:image/png;base64,` 開頭,解得開,而且寬度是 64
- `sources` 的每個 id 都有 name 與 url,url 對得回 id
- 抓到 + 失敗 = 40,沒有無聲消失的
- `retrievedAt` 是真的抓取時間
