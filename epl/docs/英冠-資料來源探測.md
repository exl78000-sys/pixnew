# 英冠資料來源探測(2026-08-28)

做英冠之前先把來源逐個打過一次。**這一份的重點是那些「拿不到」的結論** ——
拿得到的東西下一個人自己會發現,拿不到的如果沒寫下來,他會再花一次時間重試。

CLAUDE.md 的鐵則三講過:斷言某個資料拿不到之前,要先確認自己試的是不是對的端點。
所以下面每一條「沒有」都附**對照組** —— 同一個請求換一個聯賽會回資料,
才證明是那個聯賽沒有,不是我打錯。

## 拿得到的

### openfootball / football.json — `en.2.json`

靜態檔、Public Domain、`raw.githubusercontent.com`(專案允許的下載方式)。

| 賽季 | 場次 | 說明 |
|---|---|---|
| 2023-24 | 557 | 552 聯賽 + 5 附加賽,全部有比分 |
| 2024-25 | 557 | 同上 |
| 2025-26 | 557 | 同上 |
| 2026-27 | 552 | 附加賽還沒排;開季 21 場已完賽 |

**兩個形狀陷阱:**

1. 比分有兩種寫法。多數是 `{"score":{"ft":[2,1],"ht":[1,0]}}`,
   但 **0:0 收場的寫成 `{"score":[0,0]}`**(陣列,沒有 ht)。
   只認 `score.ft` 的話,2025-26 會數成「552 場只有 518 場有比分」,
   於是誤以為上游缺了 34 場 —— 我就這樣誤判過一次,還把錯的數字寫進了三個檔案的註解。
   adapter(`lib/adapters/openfootball.mjs` 的 `readScore`)本來就兩種都讀。
   那 34 場拿 football-data.co.uk 逐場核對過,**全部真的是 0:0**。

2. 升級附加賽的 `round` 不是 `Matchday N`(2023-24 寫 `Semifinals` / `Final`,
   2025-26 寫 `Playoffs`)。它們**跟聯賽撞「主客組合」這個鍵** ——
   附加賽 `NOR|LEE 0-0` 與聯賽 `NOR|LEE 2-3` 是同一個鍵,
   拿來跟別的來源配對會每季報 5 場假的「比分不符」。
   現在在補比分之前就標 `stage`,標了的不參與配對、不進積分榜、不進模型,但留在賽果裡。

## 拿不到的(附對照組)

### Understat 沒有英冠 —— 這是驗證過的否定

`POST https://understat.com/main/getPlayersStats/`,body `league=<X>&season=2025`:

| league | HTTP | success | 球員數 |
|---|---|---|---|
| `EPL` | 200 | true | **537** |
| `La_liga` | 200 | true | **600** |
| `Championship` | 200 | true | **0** |
| `EFL_Championship` | 200 | true | 0 |
| `English_Championship` | 200 | true | 0 |
| `ENG_Championship` | 200 | true | 0 |

`GET https://understat.com/getTeamData/{英冠球隊}/2025` → **404**
(試過 `Leeds`、`Birmingham_City`;同一個端點對英超西甲球隊是有資料的)。

同一個請求形狀在兩個聯賽回得出 537 與 600 人,英冠四種寫法全回空陣列 ——
**所以是 Understat 不做這個聯賽,不是端點打錯。**

注意它回的是 `HTTP 200` 加 `success: true` 加空陣列,不是錯誤。
只看 `res.ok` 的排程會每天回報成功而實際一筆都沒抓到(CLAUDE.md 有這一條)。

連帶做不出來的:xG、球員逐季數據、進球情境分類、風格百分位。

### FPL 只有英超

不用試 —— FPL 是英超官方的遊戲,沒有其他聯賽。

### 所以英冠做到哪一層

做得出來:賽程、賽果、積分榜、逐場統計、近況、歷來交手、
Poisson + Elo 模型、賽季模擬、走查回測、模型 vs 市場。

做不出來:球員、xG、陣容、傷停、教練(教練是人工,不是拿不到)、賽後統計。

導覽列只掛做得出來的三頁(`index` / `teams` / `model`),
其餘的頁網址仍然進得來,由 `LeagueGap` 講一句實話 —— 不是給一個空白頁。

## 隊名對照是怎麼配出來的(不是用名字猜的)

E1 用簡稱(`Wolves`、`Sheffield Weds`、`QPR`),openfootball 用全名
(`Wolverhampton Wanderers FC`)。36 支裡只有 10 支正規化之後直接相等。

**沒有用名字相似度配。** 用的是指紋:同一季裡,一支球隊的
「每一場的日期 + 主客 + 進球 + 失球」這組集合,在兩份來源裡會大量重合,
而不同球隊之間幾乎不可能重合。門檻是「重合 ≥ 20 場,且最佳為次佳的 4 倍以上」。

32 支這樣就配定了(重合 46~140 場,次佳都在 11 以下)。
剩下 4 支是本季剛升降的球隊、只踢了一兩場,指紋不夠 ——
而護欄在這裡抓到一個**錯配**:`Lincoln → Preston North End`(重合 2、次佳也 2)。
第二輪改用「日期 + 主客 + 已確定的對手」的賽程指紋(不看比分,所以第一輪就成立),
四支全部定案,Lincoln 修正為 `Lincoln City FC`。

這就是 CLAUDE.md 那條「盃賽寬鬆比對會對錯球隊」的第三次出現。
結果寫在 `data/manual/teams-championship.json` 的 `fd` 欄,
`npm test` 有一條守著「兩份來源的每個隊名都對得上名冊」。

## 積分榜跟官方可能差一名(扣分)

英冠幾乎每季都有扣分處分(財政違規等),而比賽資料裡沒有扣分。

實測 2025-26:我們從比分算出來的後三名是 BLB、OXF、SHW,
但**實際離開聯賽的是 LEI、OXF、SHW**。LEI 與 BLB 同為 52 分,
LEI 淨勝球還比較好(−10 vs −14),照比分算 LEI 是第 21 名。

本站**沒有扣分的資料來源**,所以不去猜一個數字填上。
做法是每次 build 自動對帳(我們的後三名 vs 實際降級的隊伍),
對不上就把差異寫進 `meta.tableCaveat` 並顯示在首頁的「目前資料界線」。
