# 英超戰情室(PL War Room)

以英超為準的比賽分析平台:**球員、戰術、教練、動態、預測**五個面向,全部建立在真實資料上。
免安裝套件、免打包工具 —— 只要有 Node 18+,三行指令就能在本機跑起來。

```bash
cd epl
npm run fetch     # 抓原始資料(已附在版控裡,首次可略過)
npm run build     # 跑分析引擎,產生前端資料集
npm run serve     # 開 http://localhost:5173
```

想寄給別人、或不想開伺服器?打包成單一 HTML 檔,直接雙擊就能看:

```bash
npm run bundle    # → dist/warroom.html(約 1.6 MB,含全部資料與字體,零外部請求)
```

想接上進行中的比賽:

```bash
npm run live      # 官方 FPL API,比賽進行中逐分鐘更新
npm run build     # 併進網站
```

## 這個平台能回答什麼

| 頁面 | 回答的問題 |
|---|---|
| **總覽** | 這季誰會贏?模擬一萬次賽季後,每隊的期望積分、奪冠/前四/降級機率 |
| **實時戰況** | 現在幾比幾、還有多久開賽、這場實際排出什麼陣容?即時比分、開賽倒數、場中勝率與真實陣型解讀 |
| **賽程預測** | 這場誰會贏、可能幾比幾?比分機率矩陣、大小球、雙方進球、交手紀錄 |
| **球隊** | 這隊上季到底怎麼贏、怎麼輸?主客落差、半場行為、Elo 走勢、陣容與傷停 |
| **戰術** | 這隊實際把人擺在哪?攻守四象限、人力配置、領先守不守得住、上下半場強弱 |
| **球員** | 這名球員強在哪?同位置百分位雷達、per-90 數據、兩人對比、十種排行榜 |
| **教練** | 這位教練任內成績如何?用任期日期切分比賽,自動算出各任教練的真實戰績 |
| **動態** | 現在有誰傷、有誰轉會、下一場的看點?傷停與轉會來自官方欄位,含更新日期 |

## 實時戰況怎麼運作

三種資料來源,同一套正規化格式,前端不需要知道資料從哪來:

| 來源 | 指令 | 更新頻率 | 限制 |
|---|---|---|---|
| **官方 FPL API** | `npm run live -- --source=api` | 比賽進行中**逐分鐘**更新 | 需要能連到 `fantasy.premierleague.com` |
| **GitHub 鏡像** | `npm run live -- --source=mirror --round=N` | 每輪賽後 | 不會場中更新 |
| **重播** | `npm run live -- --replay=2025-26:1` | — | 真實的歷史比賽,網站會標示「示範模式」 |

`npm run live` 預設是 `--source=auto`:先試官方 API,連不到就自動改用 GitHub 鏡像。

### 比賽進行中拿得到什麼

| 顯示的東西 | 資料怎麼來的 |
|---|---|
| 即時比分、進行分鐘 | 來源的 fixture 狀態 |
| **實際排出的先發十一人與陣型** | 出場紀錄中 `starts=1` 的球員,依位置統計人數 |
| 與該隊常態的差異 | 對照上季的人力配置(例如「後場比上季常態多 0.9 人」) |
| **換人時序** | 由出場分鐘反推(替補打 30 分鐘 ≈ 第 60 分鐘上場),標示 ≈ 為推估 |
| 場上 xG / xA | 各球員的期望進球加總 |
| **即時勝率** | 賽前 λ 依剩餘時間等比例縮放,代入目前比分做卷積;紅牌會調整雙方強度 |
| 下一球歸屬機率 | 兩個 Poisson 過程的強度佔比 |
| 門將表現 | 撲救次數、期望失球 vs 實際失球 |
| 自動戰術解讀 | 由陣型差異、xG 與比分的落差、換人時機、紅牌等條件生成 |

**沒有的東西,不會假造**:FPL 的資料沒有進球與卡牌的**發生分鐘**,所以事件不會標時間軸;
「陣型」是依 FPL 位置分類統計先發人數,邊鋒會被算進中場,不等於轉播圖上的陣型。

### 即時積分榜

本季積分榜同時吃兩個來源:openfootball 的正式賽果,以及即時來源裡「已完賽」的場次。
上游還沒更新時,即時來源的結果會先補進去,所以積分榜不用等。

### 開賽倒數

倒數用的是 **FPL 的 UTC 開球時間**,不是 openfootball 的預設時段 —— 後者有 32 場的日期與實際不符
(電視轉播改期)。時間一律換算成觀看者所在時區顯示。倒數不需要任何即時資料,永遠可用。

## 分析引擎

### 1. 比賽預測:Dixon-Coles Poisson + Elo

每隊各有進攻強度 `att` 與防守弱點 `def`,加上聯盟基準 `μ` 與主場優勢 `γ`:

```
λ主 = exp(μ + att主 + def客 + γ)      λ客 = exp(μ + att客 + def主)
```

- **時間衰減**:越近期的比賽權重越高(ξ = 0.0035/天,約半年半衰)
- **低比分修正 ρ**:Dixon-Coles 的 τ 修正,補足獨立 Poisson 低估和局的問題
- **升班馬先驗**:沒有近期英超樣本的球隊,套用「聯盟後段」強度,並在模擬時給更大的不確定性
- **Elo**:同時跑一套含進球差加權、跨季回歸平均的 Elo 評分

### 2. 為什麼最後採用「兩者平均」

`npm test` 會跑**走查回測**:重跑上季 38 輪,每一輪都只用開賽前的資料重新建模再預測,絕不偷看未來。

| 模型 | RPS ↓ | LogLoss ↓ | 命中率 ↑ |
|---|---|---|---|
| Dixon-Coles Poisson | 0.2084 | 1.0268 | 47.9% |
| Elo | 0.2085 | 1.0264 | 47.1% |
| **兩者平均(採用)** | **0.2076** | **1.0237** | **48.7%** |
| 基準線(固定 44/25/31) | 0.2274 | 1.0808 | 42.6% |

平均之後三項指標都最好,所以平台顯示的機率用平均值,單場頁面同時列出兩套模型各自的看法。

### 3. 賽季模擬

用預測強度把剩餘賽程跑一萬次。關鍵細節:**每一次模擬都重新抽一組「球隊真實強度」**
(有樣本的隊 σ=0.10,升班馬 σ=0.15,並扣掉 σ²/2 讓期望值不偏),
否則只用點估計會嚴重低估不確定性,模型會過度自信地把冠軍發給某一隊。

### 4. 戰術指標怎麼算的

| 指標 | 算法 |
|---|---|
| 人力配置(如 `4.6 - 4.3 - 1.1`) | 各位置出場分鐘 ÷ 外場總分鐘 × 10 = 平均場上人數。**注意 FPL 把邊鋒歸類為中場**,所以這是人力分佈不是轉播圖陣型;後場接近 5 = 三中衛/五後衛體系 |
| 球隊 xG | 全隊球員期望進球加總 |
| 球隊 xGA | 該隊**門將**的期望失球(xGC)加總 |
| 終結超出期望 | 實際進球 − xG,正值代表終結超常(通常難延續) |
| 門將撐場 | xGA − 實際失球 |
| 領先保分率 | 半場領先的比賽中,實際拿到的分數 ÷ 可能的最高分數 |
| 下半場增減 | 下半場淨勝球 − 上半場淨勝球 |
| 定位球威脅(代理) | 後衛 + 門將的進球佔全隊比例 |
| 主力吃重度 | 出場最多的 11 人佔全隊總出場的比例 |

### 5. 球員百分位

同位置、上季出場 **600 分鐘以上**的球員為母體,各位置有專屬的六軸雷達
(門將看撲救與零封、後衛看防守貢獻與解圍、中場看創造與威脅、前鋒看進球與終結)。

> **轉會處理**:上季數據掛在**當時效力的球隊**,不會算到新東家頭上;
> 排行榜與球員卡都會標示「上季 XXX → 本季 YYY」。

## 換季 / 更新資料

```bash
npm run fetch -- --force   # 重抓所有原始資料
npm run build              # 重跑分析
npm test                   # 確認預測引擎仍優於基準線
```

新賽季開打後只要改 `scripts/lib/sources.mjs` 的三個常數:

```js
export const CURRENT_SEASON = '2026-27';   // 進行中賽季
export const LAST_SEASON = '2025-26';      // 最近一個完整賽季
export const HISTORY_SEASONS = ['2023-24', '2024-25', '2025-26'];
```

升降級造成的新球隊,補進 `data/manual/teams.json` 即可(缺對照時 build 會直接報錯提醒)。

## 需要人工維護的部分

**教練名冊**是唯一沒有免費穩定 API 的部分,`data/manual/coaches.json` 要靠手動更新:

```jsonc
{ "team": "ARS", "name": "Mikel Arteta", "zh": "阿爾特塔", "nat": "西班牙",
  "confidence": "high",              // high / medium / low / unknown,會顯示在頁面上
  "formation": "4-3-3",
  "style": ["高位壓迫", "定位球武器化"],
  "spells": [{ "from": "2019-12-20", "to": null }] }   // to = null 代表在任中
```

只要 `spells[]` 的日期填對,**戰績是自動算的** —— 系統會用日期切分比賽,
算出每位教練(含賽季中途接手者)任內的場次、勝率與場均勝點。
名冊整理時點記在 `_asOf`,頁面上會顯示鮮度提醒與每筆資料的可信度標籤。

## 已知限制(都寫在頁面上,不藏)

- 模型只吃比賽結果與 FPL 統計,**不含轉會、傷病、賽程密度的人工調整**。夏窗大手筆補強不會反映在強度上。
- 賽季模擬用獨立 Poisson 抽樣,和局會略少於真實比例(整季總積分約高估 1%)。
- 升班馬沒有近期英超樣本,用「聯盟後段先驗」估計,不確定性明顯較大。
- 「陣型」是用出場分鐘推估的人力配置,不是實際戰術板陣型(FPL 把邊鋒算中場)。
- 定位球威脅用「後場球員進球佔比」代理,沒有真正的定位球進球分類資料。
- 外部新聞 RSS 需要能連到 BBC / Sky / Guardian;受限網路環境抓不到時會自動跳過,
  動態頁仍有傷停、轉會、賽前看點與數據敘事。
- **逐分鐘的即時比分需要官方 FPL API**;只放行 GitHub 的環境拿不到,會退回每輪更新的鏡像,
  網站上會明確標示資料來源與最後更新時間,不會把非即時的資料講成即時。
- 即時勝率假設進球速率在場上均勻分佈(實際上傷停補時略高),紅牌影響用的是經驗係數
  (該隊進攻 ×0.72、對手進攻 ×1.30),不是從本聯盟資料擬合出來的。

**預測數字僅供分析參考,不構成任何投注建議。**

## 兩種執行模式

同一份程式碼支援兩種模式,靠 `core.js` 的路由抽象切換:

| | 多頁模式 | 單檔模式 |
|---|---|---|
| 進入點 | `web/index.html`(需伺服器) | `dist/warroom.html`(可直接開) |
| 連結 | `teams.html?code=ARS` | `#teams?code=ARS` |
| 資料 | `fetch('data/*.json')` | 內嵌於 `window.__DATA__` |
| 倒數計時 | 兩者相同,純前端計算,不需要伺服器 | |
| 字體 | `fonts.css` 的 data URI | 同上,一併攤平進單檔 |

寫程式時一律用 `C.link(page, params)` 與 `C.go(page, params)`,不要寫死 `.html` 連結,
兩種模式才會同時正確。
