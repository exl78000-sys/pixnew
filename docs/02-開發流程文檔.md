# 02 開發流程文檔 —《AI 魚缸公寓》

版本:v1.0(2026-07-13)
路線:MVP 先行,逐步進化。每個里程碑結束時都有**可玩版本**與**製作人驗收**。

---

## 1. 里程碑總覽

```
M0 環境與素材(0.5 週)
 └→ M1 會動的公寓(1~2 週):地圖 + 3 室友 + 固定作息 + 相遇會聊天
     └→ M2 記憶與自由意志(1~2 週):記憶流 + 自由規劃,行為開始「自己長出來」
         └→ M3 完整社會(1~2 週):6 室友 + 反思 + 關係/感情系統
             └→ M4 節目化(1~2 週):事件卡 + 週報 + 打磨
```

每個里程碑 = 數個交辦任務(見 `03-交辦事項文檔`),每個任務有對應提示詞(見 `04`)。

---

## 2. 各里程碑定義

### M0 環境與素材

**目標**:任何人 clone 專案後 10 分鐘內能跑起來一個空白 Phaser 畫面。

交付物:
- Monorepo 骨架(client / server / shared / content)、TypeScript、ESLint 設定
- LimeZu 素材包與 Cubic 11 字型放入 `client/public/assets/`(製作人下載,授權留存)
- `.env.example` 與 README 啟動說明(`npm run dev` 一鍵啟動前後端)

驗收標準:
- [ ] `npm install && npm run dev` 後瀏覽器顯示 Phaser 畫布與「Hello 公寓」文字(Cubic 11 字型)
- [ ] 後端 `/health` 回 200;WebSocket 能連上並收到心跳

### M1 會動的公寓

**目標**:證明「看 AI 生活」的畫面成立。

交付物:
- Tiled 公寓地圖(客廳/廚房/浴室/3 間臥室)載入渲染
- 3 個室友 sprite,A* 尋路行走,固定作息表(寫死的 JSON 日程)
- 模擬時鐘與速度控制(暫停/1x/4x/16x)
- 相遇對話:兩人同房間且距離近 → Sonnet 生成 4~8 輪對話,氣泡逐字顯示
- LLM Router(分層路由 + token 記帳 + 每日花費上限保險絲)

驗收標準:
- [ ] 連續跑 2 個模擬日不崩潰、角色不卡牆
- [ ] 至少看到 3 段自然的中文對話,內容符合人設
- [ ] 花費記帳板顯示當日 token 成本,且與 Anthropic console 對得上(±20%)

**M1 是方向驗證點**:如果對話不好看,先調 prompt 再進 M2。

### M2 記憶與自由意志

**目標**:拿掉寫死的作息,行為由記憶+規劃驅動——「魔法」出現的一步。

交付物:
- 記憶流(寫入/重要度評分/加權檢索)+ SQLite 持久化
- 每日規劃:06:00 由 Sonnet 依人設+昨日記憶生成日程,遞迴分解到行動
- 決策 tick:Haiku 依日程+感知+記憶決定下一步(可偏離日程)
- 對話內容雙方寫入記憶,之後的對話能引用先前聊過的事
- 存檔/讀檔(世界+記憶完整快照)

驗收標準:
- [ ] 兩個室友第二次聊天時能自然提起第一次聊的內容
- [ ] 同一室友連續三天的日程有變化且與其經歷相關
- [ ] 中斷後讀檔續跑,行為連貫

### M3 完整社會

**目標**:上到 6 個室友,出現關係與感情——「海王」可能誕生的一步。

交付物:
- 6 個室友(人設由製作人在 `content/personas/` 定稿)
- 反思機制:重要度累積觸發,產出高階結論(「我好像喜歡上了…」)寫回記憶
- 關係系統:好感/熟悉度隨互動變動;關係摘要注入對話 prompt
- 角色面板:目前行動、心情、關係網、最近記憶(玩家可窺探內心)
- 併發與效能:6 agent 決策錯峰排程,對話期間鎖定參與者

驗收標準:
- [ ] 連跑 3 模擬日,出現至少一段「非腳本」的關係發展(玩家能講出一個故事)
- [ ] 反思內容合理,沒有幻覺式記憶(引用不存在的事件)
- [ ] 6 室友滿載時每模擬日成本 ≤ $3(未含 caching)

### M4 節目化

**目標**:從「模擬器」變成「遊戲」。

交付物:
- 事件卡系統:8~12 張卡(製作人出創意),投放後改變世界狀態+植入高重要度記憶
- 週報:每模擬週結算,Sonnet 把高重要度事件剪成一集節目時間軸
- Prompt caching 上線(人設穩定前綴),成本優化
- 打磨:BGM/音效(免費素材)、UI 潤飾、新手引導一頁

驗收標準:
- [ ] 投放事件卡後 1 個模擬日內能觀察到明確的行為漣漪
- [ ] 週報可讀、有戲劇性,願意截圖分享的程度
- [ ] caching 後成本較 M3 降 ≥ 30%

## 3. 協作循環(每個任務都走這個流程)

```
架構師(Claude)                    AI 助手                  製作人(你)
────────────────                ──────────               ─────────────
1. 從 03 挑任務、確認依賴已完成
2. 把 04 對應提示詞交給 AI 助手 ──→ 3. 依提示詞實作
                                   4. 自測後提交 PR/commit
5. 程式碼審查 ←──────────────────────┘
6. 審查通過 → 通知製作人 ─────────────────────────────→ 7. 試玩驗收
8. 依回饋開修正任務(回到 1)  ←───────────────────────── 8. 回饋(好/要改哪裡)
```

規則:
- **一次一個任務**:AI 助手同時只執行一個提示詞,避免互相衝突。
- **提示詞是合約**:提示詞裡的驗收標準沒過,任務不算完成。
- 里程碑結束才合併回主線;里程碑內任務走 feature branch。

## 4. 版控慣例

- 分支:`feat/M1-T3-pathfinding` 形式(里程碑-任務編號-短名)
- Commit:`[M1-T3] 實作 A* 尋路與角色移動`
- 每個里程碑打 tag:`v0.1-M1` … `v0.4-M4`

## 5. 測試策略

| 層 | 方式 |
|---|---|
| 模擬邏輯(時鐘/尋路/記憶檢索評分) | Vitest 單元測試,不打 API |
| LLM 呼叫 | Router 提供 mock 模式(錄製/回放 JSON),CI 與本地測試零成本 |
| 整合 | 「快轉煙霧測試」:mock 模式跑 1 模擬日,斷言無錯誤、無角色卡死 |
| 體驗 | 製作人每里程碑真 API 試玩 ≥ 30 分鐘,填驗收清單 |

## 6. 風險與應對

| 風險 | 訊號 | 應對 |
|---|---|---|
| 對話空洞/客套 | M1 驗收不過 | 調人設寫法(具體怪癖>形容詞)、對話 prompt 加「衝突與慾望」指引 |
| 行為循環卡死 | 同行動重複 >3 次 | 決策 prompt 注入「你剛剛已做過 X」;行為多樣性懲罰 |
| 幻覺記憶 | 反思引用不存在事件 | 反思 prompt 附原始記憶並要求逐條引用來源 id |
| 成本失控 | 記帳板超標 | 保險絲自動暫停;調大決策 tick;降低對話輪數上限 |
| 素材授權 | — | 只用 LimeZu 免費版允許範圍;商用前購買 $4 完整版 |
| API 中斷 | 呼叫失敗 | Router 重試+退避;連續失敗進入「睡眠模式」(角色原地待機) |

## 7. 完成的定義(DoD)

一個任務算完成,當且僅當:
1. 提示詞內驗收標準全數通過(AI 助手自測 + 架構師複核)
2. `npm run lint && npm run test` 通過
3. 不破壞既有功能(煙霧測試通過)
4. 涉及玩家可見變化的,製作人試玩點頭
