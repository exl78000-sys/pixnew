# 04 AI 助手提示詞文檔 —《AI 魚缸公寓》

版本:v1.0(2026-07-13)

## 使用方式

1. 依 `03-交辦事項文檔` 的順序與依賴挑任務。
2. 把下方【通用前置說明】+ 該任務的提示詞,一起貼給 AI 助手(如 Claude Code),並確保它能存取本 repo。
3. AI 助手完成後必須逐條回報驗收標準的通過情況;架構師審查後才標記 ✅。

## P-06(M1-T4)LLM Router

```
【任務】實作統一的 LLM 呼叫層。這是全專案唯一碰 Anthropic SDK 的地方。

server/src/llm/Router.ts,介面:
  route(kind, payload) → Promise<parsed JSON>
  kind ∈ {action_decision, talk_intent, dialogue_turn, daily_plan, reflection, weekly_recap}
- 路由:action_decision / talk_intent → claude-haiku-4-5;其餘 → claude-sonnet-5。
- 每種 kind 一個提示詞模板,放 server/src/prompts/(本任務先放 stub,後續任務填內容)。
- 輸出用 output_config json_schema 約束;解析失敗自動重試 1 次。
- 記帳:累計每模型 in/out token 與美元成本(單價寫在設定檔);
  提供 getLedger();當日成本超過 .env 的 DAILY_BUDGET_USD(預設 5)→
  發出 budget_exceeded 事件並拒絕新呼叫(模擬層收到後暫停時鐘)。
- mock 模式:LLM_MODE=mock 時從 fixtures JSON 回放回應(錄製工具:LLM_MODE=record)。
- 失敗處理:429/5xx 指數退避重試 3 次;連續失敗發 llm_down 事件。

【驗收標準】
1. mock 模式下 npm run test 不需要 API key 全數通過。
2. 真實模式下呼叫一次 dialogue_turn,ledger 正確累計成本。
3. 把 DAILY_BUDGET_USD 設 0.01 後連續呼叫,保險絲觸發且模擬暫停。
```

## P-08(M1-T7)相遇對話

```
【任務】兩位室友相遇時生成即時對話。

- 相遇判定:同房間且距離 ≤ 3 格、雙方皆非睡眠/盥洗中、距上次交談 ≥ 60 模擬分。
- 流程:route("talk_intent")(Haiku,輸入雙方人設摘要+當前動作,輸出 {talk:bool, topic})
  → talk 為真則雙方進入交談狀態(停下、面對面),
  route("dialogue_turn") 逐輪生成(Sonnet),4~8 輪,每輪輸出 {speaker, text, end:bool}。
- 對話 prompt 填入:雙方人設全文、當前情境(時間/地點/剛在做什麼)、本次話題。
  要求口語、符合 speech_style、可以有小衝突,禁止客套空話。每輪 ≤ 40 字。
- client/ui/SpeechBubble:頭頂氣泡逐字顯示(Cubic 11),自動換行,輪流出現。
- 對話全文記入 events 表(kind="dialogue")。

【驗收標準】
1. 一個模擬日內自然發生 ≥ 3 段對話,無同時多段重疊(一人同時只能在一段對話)。
2. 對話內容明顯反映各自人設與 speech_style(製作人抽查)。
3. 對話期間兩人不執行作息;結束後回歸日程。
```

## P-09(M2-T1)記憶流 + SQLite 持久化

```
【任務】實作 Generative Agents 的記憶流核心。

- server/persist/Db:better-sqlite3,建 01 文檔第 4 節的全部資料表;migrations 簡單版本化。
- server/agent/MemoryStream:
  write(agentId, kind, content, importance, simTime)
  retrieve(agentId, query, k=8) → 加權排序 top-k:
    score = 0.5*recency + 0.3*importance/10 + 0.2*relevance
    recency = exp(-Δt/1440)(以模擬分鐘,一天衰減 ~63%)
    relevance = query 與 content 的關鍵詞重疊率(jieba 或簡單 n-gram 均可,選一種並註明)
  存取後更新 last_access。
- 掛接:行動完成、對話結束、感知到他人行為時各寫一條 observation 記憶;
  重要度先用規則版(對話 5、日常 2、事件卡 8),M2-T3 後改由 Haiku 評分。

【驗收標準】
1. 單元測試:寫入 20 條混合記憶後,retrieve 對「做飯」query 回傳的 top-3 合理
  (含固定測資與明確斷言)。
2. 重啟 server 後記憶仍在(SQLite 檔案持久化)。
3. 效能:單次 retrieve 在 1000 條記憶下 < 10ms。
```
