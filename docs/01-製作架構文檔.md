## 1. 遊戲概述

### 1.1 一句話定位

> 你是實境秀製作人,AI 室友是演員,劇本沒人寫——它們自己活出來。

### 1.2 核心體驗

- 俯視 2D 像素公寓,6 個 AI 室友(MVP 先做 3 個)自主生活:起床、做飯、健身、聊天、曖昧、吵架。
- 每個室友由大語言模型驅動,擁有**記憶流、反思、每日規劃**三大認知能力(史丹佛 Generative Agents 架構)。
- 玩家不操控任何角色,唯一的干預手段是**事件卡**:停電一晚、送一台跑步機、塞一封匿名情書。
- 每個遊戲週自動結算一集「節目」:把本週高重要度事件剪成時間軸回顧。

### 1.3 玩家動機

看戲 + 實驗心:「如果我這樣戳一下,它們會怎樣?」

### 1.4 明確不做(Non-goals)

- 不做玩家角色、不做戰鬥、不做任務系統。
- MVP 階段不做多人連線、不做手機版、不做 WebGL 版(桌面 Windows 優先)。
- 不追求照片級美術,像素素材包風格統一即可。

| 層 | 選擇 | 版本 | 理由 |

| 美術素材 | 製作人自備素材包(`Assets/Art/Raw/`,不進版控) | — | 已下載於本機;M1-T1 整理匯入 |

MonoBehaviour 只負責驅動與呈現。API key 存本機 `StreamingAssets/config.json`(不進版控)。

## 3. 系統架構

### 3.1 總覽

```
┌──────────────────────── Unity 遊戲程序 ────────────────────────┐
│                                                                │
│  呈現層(MonoBehaviour / uGUI)                                  │
│  ApartmentScene(Tilemap)/ RoommateView(sprite+動畫)          │

│        ▲ 讀取狀態、播放表現                 │ 玩家輸入            │
│  ──────┼──────────────────────────────────▼─────────────────  │
│  模擬核心(純 C#,不依賴 UnityEngine,可單元測試)                 │
│  ┌───────────┐  ┌──────────────┐  ┌──────────────┐            │
│  │ SimClock  │→│ Agent 引擎     │→│ WorldGrid     │            │
│  │ (tick)    │  │ 感知→檢索→    │  │ 房間/物件/    │            │
│  │           │  │ 決策→行動     │  │ A* 尋路      │            │
│  └───────────┘  └──────┬───────┘  └──────────────┘            │
│  ┌───────────┐  ┌──────▼───────┐  ┌──────────────┐            │
│  │ Event     │  │ MemoryStream │  │ SaveSystem   │            │
│  │ System    │  │ Reflection   │  │ (JSON 快照)  │            │
│  │ (卡/週報)  │  │ Planner      │  │              │            │
│  └───────────┘  └──────────────┘  └──────────────┘            │
│  ──────────────────────┬─────────────────────────────────────  │
│  LLM 層(MonoBehaviour,唯一碰網路的地方)                        │
│  LlmRouter(分層路由/mock/提示詞模板)                            │
│   └ AnthropicClient(UnityWebRequest/重試/記帳/保險絲)          │
```

### 3.2 呈現層(`Assets/Scripts/View/`,M1 起建立)

| 模組 | 職責 |
|---|---|
| `ApartmentScene` | Tilemap 公寓場景管理;鏡頭(固定全屋,可 1x/2x 縮放) |
| `RoommateView` | 角色 SpriteRenderer + Animator(四向行走/待機);依模擬座標插值移動 |
| `SpeechBubble` | 世界座標跟隨的對話氣泡(Cubic 11、逐字顯示、自動換行) |
| `Hud` | 時鐘、日期、速度控制(⏸/1x/4x/16x)、花費記帳板 |
| `RoommatePanel` | 點角色開側欄:行動、心情、關係網、最近記憶 |
| `EventCardDeck` | 事件卡手牌與拖曳投放 |
| `WeeklyRecap` | 週報全螢幕時間軸 |

呈現層是**純顯示**:每幀讀模擬核心的狀態來渲染,玩家輸入轉成對模擬核心的指令。

### 3.3 模擬核心(`Assets/Scripts/Core|Sim|Agents/`,純 C#)

| 模組 | 職責 |
|---|---|
| `Core/SimClock` | 1 tick = 1 模擬分鐘;現實 2 秒 = 1 tick(1x);0/1/4/16 倍速;OnTick / OnNewDay 事件 |
| `Sim/WorldGrid` | 從 Tilemap 烘焙的邏輯網格:碰撞、房間標記、具名物件點位(bed_1、stove…);A* 尋路 |
| `Sim/WorldObjects` | 物件狀態表(冰箱有無剩菜、燈開關…);事件卡改這裡 |
| `Agents/Agent` | 單一室友認知迴圈:感知 → 記憶檢索 → 決策 → 行動 → 寫回記憶 |
| `Agents/MemoryStream` | 記憶流:寫入(附重要度)、檢索(新近度×重要度×相關性 top-k,記憶體內計算) |
| `Agents/Reflection` | 重要度累積超過閾值 → Sonnet 歸納高階結論寫回記憶流 |
| `Agents/Planner` | 模擬日 06:00 生成當日日程(Sonnet),分解為時段行動 |
| `Agents/Dialogue` | 相遇判定 → 交談意願(Haiku)→ 多輪對話(Sonnet)→ 雙方寫記憶 |
| `Agents/Relationship` | 好感/熟悉度隨互動更新;關係摘要注入對話 prompt |
| `Events/EventSystem` | 事件卡生效(改物件狀態+植入高重要度記憶)、週報結算 |
| `Core/SaveSystem` | 全世界快照(agents+memories+relationships+events+objects+clock)序列化 JSON 存 persistentDataPath;自動存檔每模擬日一次 |

### 3.4 LLM 層(`Assets/Scripts/LLM/`,已於 M0 建立)

| 模組 | 職責 |
|---|---|
| `LlmRouter` | 唯一入口 `Route(kind, system, user, onOk, onErr)`;kind→模型路由;mock 模式攔截;提示詞模板(M1-T4 起填入) |
| `AnthropicClient` | UnityWebRequest 呼叫 Messages API;429/5xx 指數退避重試;token 記帳;每日花費保險絲(超標→暫停時鐘) |

模擬核心**不直接依賴 LLM 層**:Agent 透過注入的 `ILlmGateway` 介面呼叫(M1-T4 定義),
單元測試時注入假實作,零成本跑完整模擬日。

### 3.5 Agent 認知迴圈(每個決策 tick)

```
感知 perceive     所在房間的物件狀態 + 附近角色 → 文字描述
   ↓
檢索 retrieve     從記憶流取 top-k 相關記憶(本地打分,不呼叫 LLM)
   ↓
決策 decide       [Haiku] 依當前日程+感知+記憶 → 下一步行動(JSON)
   ↓                └ 若遇到人且 Haiku 判定「想交談」→ 進入對話流程 [Sonnet]
行動 act          移動/使用物件/交談;更新世界狀態
   ↓
記憶 memorize     行動與見聞寫入記憶流(Haiku 一併回傳重要度 1~10)
```

決策頻率:每個 agent 每 **30 模擬分鐘**一次決策 tick(對話期間暫停),六人錯峰。
反思觸發:累積重要度 ≥ 100 時觸發一次(約 1~2 模擬日一次)。

## 4. 資料模型(C# 類別,JSON 序列化)

```csharp
// 執行期狀態(存檔即整包序列化)
class AgentState   { string Id; Vector2Int Pos; string Room; string Mood;
                     string CurrentAction; DayPlan Plan; }
class Memory       { long Id; string AgentId; MemoryKind Kind;   // Observation|Dialogue|Reflection|Plan|Event
                     string Content; int Importance;             // 1~10
                     long SimTime; long LastAccess; }
class Relationship { string AgentId; string TargetId;
                     int Affinity;      // -100 ~ 100
                     int Familiarity;   // 0 ~ 100
                     string Summary; }  // 「A 覺得 B 是…」由反思更新
class GameEvent    { long SimTime; EventKind Kind;               // Action|Dialogue|Card|Milestone
                     List<string> Actors; string Summary; int Importance; }
class WorldObject  { string Id; string Room; Vector2Int Pos;
                     Dictionary<string, object> State; }         // 如 {"power": false}
```

記憶檢索評分(記憶體內 LINQ,不花 token):
`score = 0.5·recency(exp(-Δt/1440)) + 0.3·importance/10 + 0.2·relevance(關鍵詞重疊)`
MVP 用關鍵詞匹配做 relevance;M3 若品質不足再升級(如 n-gram 或本地 embedding)。

存檔 = 上述全部集合 + SimClock 狀態 → JSON → `persistentDataPath/saves/<name>.json`。

## 5. LLM 分層與成本設計

### 5.1 路由表

| 呼叫類型(LlmKind) | 模型 | 頻率(6 室友) | 單次規模(in/out) |
|---|---|---|---|
| ActionDecision | Haiku 4.5 | ~288 次/模擬日 | ~1.5K / 0.1K |
| TalkIntent | Haiku 4.5 | ~30 次/模擬日 | ~0.8K / 0.05K |
| DialogueTurn | Sonnet 5 | ~100 turn/模擬日 | ~2.5K / 0.2K |
| DailyPlan | Sonnet 5 | 6 次/模擬日 | ~2.5K / 0.5K |
| Reflection | Sonnet 5 | ~4 次/模擬日 | ~3.5K / 0.4K |
| WeeklyRecap | Sonnet 5 | 1 次/模擬週 | ~8K / 1K |

### 5.2 成本估算(未含 caching,取整)

- Haiku:約 0.5M in + 0.04M out /模擬日 ≈ **$0.7/模擬日**
- Sonnet:約 0.3M in + 0.03M out /模擬日 ≈ **$0.9/模擬日**(優惠價 ≈ $0.6)
- **合計約 $1~2 / 模擬日**;M4 開 prompt caching(人設+系統提示為穩定前綴)可再降 30~60%。
- 保險絲已內建於 `AnthropicClient`:當日花費超過 `config.json` 的 `dailyBudgetUsd`
  (預設 $5)→ 觸發 OnBudgetExceeded → 時鐘暫停。

### 5.3 Prompt 設計原則

1. 每個 agent 的 system prompt = 固定人設全文(穩定前綴,M4 掛 cache_control)+ 當前狀態(易變,放後面)。
2. 所有決策輸出要求 JSON;Router 解析失敗自動重試 1 次。
3. 對話 prompt 附:雙方關係摘要 + 各自 top-k 相關記憶 + 最近 5 輪對話。
4. 提示詞模板集中在 `Assets/Scripts/LLM/Prompts/`;人設與事件卡放 `StreamingAssets/content/`,製作人可直接改。

## 7. 架構層級的取捨紀錄

| 決策 | 取捨 |
|---|---|
| 單一 Unity 程序(捨棄前後端分離) | 少一套同步協定與部署;模擬核心保持純 C# 以保留可測試性與快轉能力 |
| 模擬核心不依賴 UnityEngine | 可用 NUnit 直測、mock LLM 下離線跑整天;代價是座標等型別需自定或轉換 |
| JSON 快照取代 SQLite | 單機 6 角色的資料量小;整包序列化簡單可靠;若記憶量成瓶頸再換 |
| UnityWebRequest 直連 API | 避開 .NET SDK 在 Unity 的相容性風險;API 表面小(只用 /v1/messages) |
| API key 放 StreamingAssets/config.json | 單機自玩可接受;此檔已 gitignore;若日後發佈給他人,需改為代理伺服器 |
| 決策 tick 30 模擬分鐘 | 成本與生動度折衷;做成設定值 |
