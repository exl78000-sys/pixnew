# 01 製作架構文檔 —《AI 魚缸公寓》

版本:v1.0(2026-07-13)
維護者:架構師(Claude)
狀態:已依製作人決策定稿,M1 開發前的唯一架構依據

---

## 1. 遊戲概述

### 1.1 一句話定位

> 你是實境秀製作人,AI 室友是演員,劇本沒人寫——它們自己活出來。

### 1.2 核心體驗

- 俯視 2D 像素公寓,6 個 AI 室友(MVP 先做 3 個)自主生活:起床、做飯、健身、聊天、曖昧、吵架。
- 每個室友由大語言模型驅動,擁有**記憶流、反思、每日規劃**三大認知能力(史丹佛 Generative Agents 架構)。
- 玩家不操控任何角色,唯一的干預手段是**事件卡**:停電一晚、送一台跑步機、塞一封匿名情書。
- 每個遊戲週自動結算一集「節目」:把本週高重要度事件剪成時間軸回顧。

### 1.3 玩家動機

看戲 + 實驗心:「如果我這樣戳一下,它們會怎樣?」

### 1.4 明確不做(Non-goals)

- 不做玩家角色、不做戰鬥、不做任務系統。
- MVP 階段不做多人連線、不做雲端部署、不做手機版。
- 不追求照片級美術,像素素材包風格統一即可。

## 3. 系統架構

### 3.1 總覽

```
┌────────────────────────────────────────────────────────┐
│  瀏覽器(Phaser 3 前端)                                  │
│  地圖渲染 / 角色動畫 / 對話氣泡 / HUD / 事件卡 UI / 週報   │
└───────────────▲───────────────────┬────────────────────┘
                │ WebSocket(狀態推送) │ REST(存檔/設定)
┌───────────────┴───────────────────▼────────────────────┐
│  本地 Node.js 後端                                       │
│  ┌──────────────┐  ┌──────────────┐  ┌──────────────┐  │
│  │ 模擬時鐘      │→│ Agent 引擎    │→│ 世界狀態      │  │
│  │ (tick 排程)   │  │ 感知→檢索→   │  │ (房間/物件/   │  │
│  │              │  │ 決策→行動     │  │  角色位置)    │  │
│  └──────────────┘  └──────┬───────┘  └──────────────┘  │
│  ┌──────────────┐  ┌──────▼───────┐  ┌──────────────┐  │
│  │ 事件系統      │  │ LLM 路由層    │  │ SQLite       │  │
│  │ (事件卡/週報) │  │ Haiku/Sonnet │  │ 記憶流/關係/  │  │
│  │              │  │ 分層+快取     │  │ 事件/存檔     │  │
│  └──────────────┘  └──────┬───────┘  └──────────────┘  │
└───────────────────────────┼────────────────────────────┘
                            │ HTTPS
                    Anthropic API(.env 存 key)
```

### 3.2 前端模組(`client/`)

| 模組 | 職責 |
|---|---|
| `scenes/ApartmentScene` | 載入 Tiled 地圖、渲染公寓、管理角色 sprite |
| `entities/Roommate` | 角色 sprite、四向行走動畫、依後端座標插值移動 |
| `ui/SpeechBubble` | 對話氣泡(Cubic 11 字型、自動換行、逐字顯示) |
| `ui/Hud` | 遊戲時鐘、日期、模擬速度控制(暫停/1x/4x/16x) |
| `ui/RoommatePanel` | 點角色開面板:目前行動、心情、關係網、最近記憶 |
| `ui/EventCardDeck` | 事件卡手牌與投放介面 |
| `ui/WeeklyRecap` | 週報時間軸(高重要度事件回放) |
| `net/SocketClient` | WebSocket 連線、狀態同步、斷線重連 |

前端是**純顯示層**:不做任何模擬邏輯,只渲染後端推送的世界狀態。

### 3.3 後端模組(`server/`)

| 模組 | 職責 |
|---|---|
| `sim/Clock` | 模擬時鐘。1 tick = 1 模擬分鐘;預設現實 2 秒 = 1 tick,可調速/暫停 |
| `sim/World` | 世界狀態:房間、物件(含狀態,如「冰箱:有剩菜」)、角色位置;A* 尋路網格 |
| `agent/Agent` | 單一室友的認知迴圈:感知 → 記憶檢索 → 決策 → 行動 → 寫回記憶 |
| `agent/MemoryStream` | 記憶流:寫入(附重要度評分)、檢索(新近度×重要度×相關性加權 top-k) |
| `agent/Reflection` | 重要度累積超過閾值時,呼叫 Sonnet 歸納高階結論寫回記憶流 |
| `agent/Planner` | 模擬日 06:00 產生當日日程(Sonnet),遞迴分解為小時級行動 |
| `agent/Dialogue` | 相遇判定 → 是否交談(Haiku 快速判斷)→ 多輪對話(Sonnet)→ 雙方寫入記憶 |
| `agent/Relationship` | 關係值(好感/熟悉度)隨互動更新;對話 prompt 會帶入關係摘要 |
| `llm/Router` | 統一 LLM 入口:按呼叫類型路由 Haiku/Sonnet、prompt caching、重試、token 記帳 |
| `events/EventSystem` | 事件卡生效(改世界狀態 + 寫入高重要度記憶)、週報結算 |
| `persist/Db` | SQLite 存取層;存檔 = 世界狀態 + 全部記憶,可隨時中斷續跑 |
| `api/Gateway` | Fastify:REST(存讀檔、設定)+ WebSocket(狀態推送、玩家指令) |

### 3.4 Agent 認知迴圈(每個決策 tick)

```
感知 perceive     所在房間的物件狀態 + 附近角色 → 文字描述
   ↓
檢索 retrieve     從記憶流取 top-k 相關記憶(不呼叫 LLM,本地打分)
   ↓
決策 decide       [Haiku] 依當前日程+感知+記憶 → 下一步行動(JSON)
   ↓                └ 若遇到人且 Haiku 判定「想交談」→ 進入對話流程 [Sonnet]
行動 act          移動/使用物件/交談;更新世界狀態
   ↓
記憶 memorize     行動與見聞寫入記憶流(Haiku 評重要度 1~10)
```

決策頻率:每個 agent 每 **30 模擬分鐘**一次決策 tick(對話期間暫停日常決策)。
反思觸發:累積重要度 ≥ 100 時觸發一次(約 1~2 模擬日一次)。

## 4. 資料模型(SQLite)

```sql
-- 角色(人設由 JSON 設定檔載入,執行期狀態存這裡)
CREATE TABLE agents (
  id TEXT PRIMARY KEY, name TEXT, persona TEXT,      -- persona: 人設全文
  x INTEGER, y INTEGER, room TEXT,
  mood TEXT, current_action TEXT, plan_json TEXT     -- 當日日程
);

-- 記憶流(核心資料表)
CREATE TABLE memories (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  agent_id TEXT, kind TEXT,          -- observation | dialogue | reflection | plan | event
  content TEXT,                      -- 自然語言記憶內容
  importance INTEGER,                -- 1~10
  sim_time INTEGER,                  -- 模擬時間戳(分鐘)
  last_access INTEGER                -- 供新近度計分
);

-- 關係(有向:A 對 B 的看法)
CREATE TABLE relationships (
  agent_id TEXT, target_id TEXT,
  affinity INTEGER DEFAULT 0,        -- -100 ~ 100
  familiarity INTEGER DEFAULT 0,     -- 0 ~ 100
  summary TEXT,                      -- 「A 覺得 B 是…」一句話,由反思更新
  PRIMARY KEY (agent_id, target_id)
);

-- 事件記錄(週報資料來源)
CREATE TABLE events (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  sim_time INTEGER, kind TEXT,       -- action | dialogue | card | milestone
  actors TEXT,                       -- JSON array of agent ids
  summary TEXT, importance INTEGER
);

-- 世界物件狀態
CREATE TABLE world_objects (
  id TEXT PRIMARY KEY, room TEXT, x INTEGER, y INTEGER,
  state TEXT                         -- JSON,如 {"power": false}
);
```

記憶檢索評分(本地計算,不花 token):
`score = w1·recency(指數衰減) + w2·importance/10 + w3·relevance(關鍵詞/主題匹配)`
MVP 用關鍵詞匹配做 relevance;M3 若品質不足再升級為本地 embedding(transformers.js)。

## 5. LLM 分層與成本設計

### 5.1 路由表

| 呼叫類型 | 模型 | 頻率(6 室友) | 單次規模(in/out) |
|---|---|---|---|
| 行動決策 | Haiku 4.5 | ~288 次/模擬日 | ~1.5K / 0.1K |
| 重要度評分 | Haiku 4.5 | 併入決策呼叫回傳 | — |
| 交談意願判定 | Haiku 4.5 | ~30 次/模擬日 | ~0.8K / 0.05K |
| 對話(多輪) | Sonnet 5 | ~100 turn/模擬日 | ~2.5K / 0.2K |
| 每日規劃 | Sonnet 5 | 6 次/模擬日 | ~2.5K / 0.5K |
| 反思 | Sonnet 5 | ~4 次/模擬日 | ~3.5K / 0.4K |
| 週報剪輯 | Sonnet 5 | 1 次/模擬週 | ~8K / 1K |

### 5.2 成本估算(未含 caching,取整)

- Haiku:約 0.5M in + 0.04M out /模擬日 ≈ **$0.7/模擬日**
- Sonnet:約 0.3M in + 0.03M out /模擬日 ≈ **$0.9/模擬日**(優惠價 ≈ $0.6)
- **合計約 $1~2 / 模擬日**;開 prompt caching(人設+系統提示為穩定前綴)可再降 30~60%。
- 內建保險絲:`llm/Router` 記帳,單日花費超過可設定上限(預設 $5)自動暫停模擬並通知前端。

### 5.3 Prompt 設計原則

1. 每個 agent 的 system prompt = 固定人設全文(穩定前綴,掛 cache_control)+ 當前狀態(易變,放後面)。
2. 所有決策輸出用 JSON schema 約束(structured outputs),避免解析失敗。
3. 對話 prompt 附:雙方關係摘要 + 各自 top-k 相關記憶 + 最近 5 輪對話。
4. 全部提示詞集中在 `server/prompts/*.ts`,人設與事件卡放 `content/*.json5`,製作人可直接改。

## 7. WebSocket 協定(shared/protocol.ts)

伺服器 → 前端:`world_state`(全量,連線時)、`agent_update`(位置/行動/心情)、
`dialogue`(氣泡內容)、`clock`(模擬時間)、`event`(事件發生)、`budget_warning`。
前端 → 伺服器:`set_speed`、`play_card`、`save` / `load`、`request_recap`。

## 8. 架構層級的取捨紀錄

| 決策 | 取捨 |
|---|---|
| 前端純顯示、後端跑模擬 | 模擬可離線快轉、可存檔續跑;代價是要維護一份同步協定 |
| 決策 tick 30 模擬分鐘 | 成本與生動度的折衷;調小更生動但線性加價,做成設定值 |
| MVP 記憶檢索不用 embedding | 省一個依賴與延遲;關鍵詞匹配對 3~6 個角色的小世界夠用,不夠再升級 |
| JSON5 放遊戲內容 | 製作人不用碰程式碼就能改人設、加事件卡 |
